# 인증 실패 응답 문구와 거부 사유 로그

> 분류: 인증·보안 · 최근 갱신: 2026-10-28

## 한 줄 요약
인증·권한 오류 응답에는 "권한이 없습니다" 같은 일반 문구와 오류 코드만 보내고, 왜 거부했는지(토큰 모양, 세션 출처, 설정 상태)는 서버 로그에만 남긴다.

## 내용
### 응답 문구가 정보를 흘리는 경우
- "관리자 화면에서 로그인한 세션만 쓸 수 있습니다", "토큰의 특정 칸이 admin이어야 합니다", "현재 인증 방식에서는 지원하지 않습니다", "연동 서버 주소가 설정되지 않았습니다" 같은 문구는 친절해 보이지만, 공격자에게 **판정 기준과 서버 설정 상태**를 알려 준다. 토큰을 어떻게 조작하면 통과하는지, 어떤 인증 방식을 쓰는지 짐작하게 한다.
- 등록 API가 "등록되지 않은 사용자", "이미 다른 사용자에게 등록된 쿠키"처럼 경우마다 다른 문구를 주면, 응답 차이로 사용자 존재 여부나 다른 사람의 값을 확인할 수 있다(열거 공격).
- 호출하는 쪽(다른 시스템)이 우리 응답에 자기 안내 문구를 덧붙여 화면에 보여 주는 경우도 있다. 이때는 상대 시스템 담당자에게 빼 달라고 해야 한다. 우리 소스에 그 문구가 있는지 먼저 검색해 출처를 가린다.

### 바꾸는 원칙
- **상태 코드와 오류 `code` 값은 유지**한다. 호출하는 쪽은 code로 분기하므로 동작이 바뀌지 않는다. 바꾸는 것은 사람이 읽는 `message`뿐이다.
- 같은 종류의 실패는 같은 문구로 묶는다. 예: 등록 실패 401·409는 모두 "로그인 세션을 등록할 수 없습니다."
- 설정 누락처럼 운영자만 고칠 수 있는 원인은 "통신하지 못했습니다" 정도로 응답하고 ERROR 로그에 원인을 남긴다.

### 원인은 로그로: 거부 사유를 request 속성으로 넘기기
- 판정은 인터셉터에서 하고 403 응답은 컨트롤러에서 만드는 구조라면, 인터셉터가 **거부 사유를 request 속성에 담아 두고** 컨트롤러가 403을 낼 때 꺼내 WARN 한 줄을 남긴다. 판정을 한 번만 하므로 DB 조회가 늘지 않는다.
- 응답 문구를 바꾼 뒤에는 "응답별로 로그에 원인이 남는가"를 표로 점검한다. 응답만 일반화하고 로그가 없으면 운영 중 원인을 찾을 수 없다.
- 로그에 **토큰, 세션 ID, 쿠키, IP 값은 남기지 않는다**. 남기는 것은 토큰의 구조적 칸(도메인·모듈 이름 등)과 판정 결과뿐이다.
- 호출자가 마음대로 넣을 수 있는 값(토큰 안의 모듈 이름 등)을 로그에 그대로 쓰면 줄바꿈을 넣어 가짜 로그 줄을 만들 수 있다(로그 위조). 아는 값 목록에 있으면 그대로, 아니면 "기타"로 적는다.
- 누가 호출했는지는 요청 단위 접근 로그(사용자 ID, trace id)와 함께 보면 된다. 사유 로그에 사용자 정보를 중복으로 넣을 필요는 없다.

## 핵심 코드
### 1) 인터셉터: 판정하고 사유를 request 속성에 담기 (Spring MVC)
```java
// 바꿔야 할 곳: 속성 이름, 판정 메소드
public static final String REJECT_REASON = "myapp.denyReason";

@Override
public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object handler) {
    String token = resolveBearer(req);
    String userId = authService.resolveUserId(token);
    if (userId == null) { res.setStatus(401); return false; }      // 인증 실패는 여기서 끝

    String reason = authService.adminRejectReason(token);           // null 이면 관리자 세션
    if (reason == null) {
        req.setAttribute("adminSession", Boolean.TRUE);
    } else {
        req.setAttribute(REJECT_REASON, reason);                     // 응답에는 쓰지 않는다
    }
    return true;
}
```

### 2) 판정 메소드: 값 대신 구조만 담은 사유
```java
public String adminRejectReason(String token) {
    TokenParts p = cipher.tryParse(token);
    if (p == null) return "해석할 수 없는 토큰";
    if (!"admin".equals(p.getModule())) {
        return "관리자 토큰 모양이 아님(모듈=" + safeLabel(p.getModule()) + ")";
    }
    Session s = sessionRepo.find(p.getSessionId());
    if (s == null) return "등록된 세션 없음";
    if (!"admin".equals(s.getIssuedFor())) return "관리자용으로 발급된 세션이 아님";
    return null;
}

// 호출자가 넣을 수 있는 값은 아는 값만 그대로, 나머지는 "기타" (줄바꿈 삽입 방지)
private static String safeLabel(String v) {
    return ("admin".equals(v) || "widget".equals(v)) ? v : "기타";
}
```

### 3) 컨트롤러: 일반 문구로 응답하고 사유는 WARN
```java
private ResponseEntity<Map<String, Object>> forbidden(HttpServletRequest req) {
    log.warn("forbidden admin api method={} uri={} reason={}",
             req.getMethod(), req.getRequestURI(), req.getAttribute(REJECT_REASON));
    Map<String, Object> body = new LinkedHashMap<>();
    body.put("success", false);
    body.put("code", "FORBIDDEN");                        // 호출하는 쪽이 분기하는 값은 그대로
    body.put("message", "이 API를 호출할 권한이 없습니다.");  // 판정 기준을 드러내지 않는 문구
    return ResponseEntity.status(403).body(body);
}
```

### 4) 같은 종류 실패는 같은 문구, 원인은 각각 로그
```java
if (!userExists(userId)) {
    log.warn("세션 등록 거부: 없는 사용자. userId={}", userId);
    return error(401, "UNAUTHORIZED", "로그인 세션을 등록할 수 없습니다.");
}
if (ownedByOther(cookieHash, userId)) {
    log.warn("세션 등록 거부: 다른 사용자에게 등록된 값. userId={}", userId);
    return error(409, "CONFLICT", "로그인 세션을 등록할 수 없습니다.");
}
if (consoleUrl == null || consoleUrl.isEmpty()) {
    log.error("세션 등록 실패: 연동 주소 설정 없음");
    return error(503, "UNAVAILABLE", "연동 서버와 통신하지 못했습니다.");
}
```

## 주의할 점
- 문구만 바꾸고 code까지 바꾸면 호출하는 쪽의 오류 처리가 깨진다. 바꾸기 전에 호출 측이 무엇으로 분기하는지 확인한다.
- 응답 문구를 비교하는 테스트가 있으면 함께 고친다. 없으면 없다는 것도 확인해 둔다.
- 개발 편의를 위해 자세한 문구가 필요하면 응답이 아니라 로그 레벨이나 개발 환경 전용 설정으로 해결한다.
- 401(누구인지 모름)과 403(누구인지는 알지만 권한 없음)을 섞지 않는다. 403이 났다면 인증은 통과한 것이므로 원인 범위가 좁혀진다.
