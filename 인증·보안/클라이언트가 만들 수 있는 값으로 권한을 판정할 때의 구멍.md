# 클라이언트가 만들 수 있는 값으로 권한을 판정할 때의 구멍

> 분류: 인증·보안 · 최근 갱신: 2026-10-23

## 한 줄 요약
토큰의 접두어, 난독화된 문자열, `X-Forwarded-For` 헤더처럼 호출자가 직접 만들거나 바꿀 수 있는 값으로 "관리자 콘솔 요청"·"내부 서버 요청" 같은 권한을 판정하면 위조된다. 판정 근거는 서버만 쓸 수 있는 값(서버가 저장한 세션 속성, 서버 키 서명, 실제 접속 IP)이어야 한다.

## 내용
### 난독화는 보안이 아니다
- 글자를 고정 공식으로 숫자열로 바꾸는 식의 "인코딩"은 키가 코드에 있거나 규칙이 공유되어 있으면 누구나 같은 값을 만들 수 있다.
- 예: 세션 ID 하나로 `WIDGET\{세션ID}\assistant`와 `ADMIN\{세션ID}\console` 두 토큰을 만들고 첫 칸으로 권한을 가르는 설계. 세션 ID를 아는 사람(브라우저 쿠키로 자기 세션 ID를 볼 수 있는 일반 사용자, 위젯 토큰을 받은 외부 서버)은 접두어만 바꿔 관리자용 토큰을 만들 수 있다. 세 번째 칸 같은 조건을 더해도 그것 역시 호출자가 쓰는 글자라 막지 못한다.
- 다만 세션 존재 확인이 있으면 임의로 만든 세션 ID는 통과하지 못한다. 위조로 얻는 것은 "자기 세션으로 더 넓은 API를 부르는 것"으로 좁혀진다. 피해 범위를 따져 우선순위를 정한다.

### X-Forwarded-For는 조작할 수 있다
- 클라이언트 IP를 `X-Forwarded-For` 첫 값으로 읽어 세션 데이터에 저장하면, 사용자가 헤더에 임의 문자열을 넣어 그 칸을 원하는 값으로 만들 수 있다.
- 세션 값을 구분자(예: `///`)로 이어 붙여 저장하는 구조라면, 헤더에 구분자를 넣어 뒤의 칸(부서, 역할 등)까지 밀어 바꾸는 주입도 가능하다.
- 앞단 프록시가 클라이언트가 보낸 헤더를 덮어쓰는지, 그대로 넘기는지에 따라 실제 위험이 달라진다. 확인 전에는 조작 가능하다고 가정한다.

### 무엇으로 판정해야 하나
| 근거 | 위조 가능성 | 비고 |
|---|---|---|
| 토큰 접두어·형식 | 가능 | 형식 검사로만 쓴다 |
| 요청 헤더(X-Forwarded-For 등) | 가능 | 신뢰할 프록시가 덮어쓴 경우에만 |
| 서버가 저장한 세션 속성(별도 컬럼) | 불가 | 등록 경로가 검증된 경우에만 값이 써지게 한다. 다른 문자열과 이어 붙여 저장하지 않는다 |
| 서버 키로 만든 서명(HMAC) | 불가 | 상대 시스템이 서명 토큰을 쓰도록 바뀌어야 한다. 다중 서버면 키를 공유해야 한다 |
| 실제 접속 IP(`getRemoteAddr`) 허용 목록 | 어려움 | 프록시·로드밸런서 뒤면 그 장비 IP가 보여 효과가 약하다. 허용된 서버가 장악되면 뚫린다 |

- IP 대역을 문자열 앞부분으로 비교할 때는 점으로 끝내야 한다(`10.1`은 `10.10.x`, `10.100.x`까지 맞는다).

### 예외 계정을 허용할 때
- "사용자 DB에 없는 계정도 통과"처럼 검사를 건너뛰는 예외를 만들면, 그 예외 표시가 위조 가능한 값에 걸려 있지 않은지 먼저 본다.
- 검사를 건너뛰는 조건으로 "칸이 비어 있으면 통과" 같은 기존 규칙이 있으면, 예외 세션이 다른 경로(예: 웹 화면 로그인)에서 그 규칙으로 통과되지 않는지도 확인한다. 빈칸 대신 실제로는 존재하지 않는 표시값을 넣어 다른 경로에서는 실패하게 만드는 방법이 있다.

## 예시
```java
// 나쁜 예: 토큰 접두어로 관리자 권한 부여
if (token.startsWith("ADMIN\\")) grantAdmin();

// 나은 예: 서버가 등록 시 저장한 세션 속성으로 판정
Session s = sessionRepo.find(sessionIdFrom(token));
if (s != null && "CONSOLE".equals(s.getType())) grantAdmin();
```

## 주의할 점
- 판정 방식을 바꾸면 기존 연동 경로(예: SSO로 들어와 등록 절차를 거치지 않은 세션)가 깨지지 않는지 함께 본다.
- 설계상 한계를 알고도 받아들이기로 했다면, 무엇이 열려 있는지(누가, 어떤 API를, 어떤 범위로)를 문서로 남긴다.
