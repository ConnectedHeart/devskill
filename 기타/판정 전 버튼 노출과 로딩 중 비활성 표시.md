# 판정 전 버튼 노출과 로딩 중 비활성 표시

> 분류: 기타 · 최근 갱신: 2026-11-10

## 한 줄 요약
문서·데이터가 다 열린 뒤에 "이 사용자에게 어떤 버튼을 보일지" 정하는 화면은, 판정 전 기본 버튼이 눌리면 상태가 꼬인다. 버튼을 숨기면 화면이 비어 보이므로, 바로 보여 주되 흐리게 하고 클릭을 막았다가 판정이 끝나면 푼다.

## 내용
- 흔한 구조: 페이지가 열리면 기본 버튼 줄이 바로 그려지고, 무거운 본문(편집기, 문서 뷰어)이 다 열린 뒤 콜백에서 권한·역할에 따라 버튼을 숨기거나 보인다.
- 버그: 로딩 중에 사용자가 기본 버튼(예: 편집모드)을 누르면 그 처리기가 다른 버튼을 숨긴다. 뒤이어 판정 콜백이 "이 역할은 편집 불가"로 그 버튼까지 숨기면 아무것도 못 하는 화면이 남는다. 두 처리가 서로를 모른 채 같은 버튼 상태를 바꾸는 경쟁 상태다.
- 해결 선택지
  1. **판정 전 숨김** — 확실하지만 로딩이 길면 위쪽이 비어 "버튼이 없다", "버그 같다"는 반응이 나온다.
  2. **판정 전 비활성(권장)** — 버튼 줄은 그대로 보이되 흐리게 하고 `pointer-events:none`으로 클릭을 막는다. 판정 콜백의 성공·실패 양쪽에서 풀어 준다. 닫기처럼 언제나 눌러도 되는 버튼은 다른 묶음으로 둬서 막지 않는다.
- 실패 경로를 꼭 챙긴다. 성공 콜백에서만 풀면 본문 열기 실패 시 버튼이 영원히 막힌다.
- 같은 패턴이 다른 뷰어(다른 문서 형식의 창)에도 있으면 함께 고친다. 하나만 고치면 같은 신고가 다시 온다.

## 핵심 코드
```html
<style>
  .btn-wait { opacity: .4; pointer-events: none; }
</style>
<ul id="actionButtons" class="btn-wait">
  <li><button id="btnEdit">편집</button></li>
  <li><button id="btnApprove">승인</button></li>
</ul>
<ul id="alwaysButtons"><li><button id="btnClose">닫기</button></li></ul>
```

```javascript
// 본문이 다 열린 뒤 호출되는 콜백 (성공·실패 모두 여기로)
function onContentReady(ok) {
  if (ok) {
    applyButtonsByRole();          // 역할별로 버튼 숨김/표시
  }
  $('#actionButtons').removeClass('btn-wait');   // 성공·실패 모두 풀기
}

// 키보드 접근까지 막아야 하면 disabled도 함께
function setWaiting(on) {
  $('#actionButtons button').prop('disabled', on);
}
```

## 주의할 점
- `pointer-events:none`은 마우스만 막는다. 탭 키·Enter로 누를 수 있으면 `disabled`도 같이 걸거나, 처리기 맨 앞에서 준비 여부를 검사한다.
- 로딩이 매우 길다면 비활성 표시는 근본 해결이 아니다. 본문 로딩 구간(외부 편집기 로드, 문서 열기, 후처리)별 시간을 재서 느린 구간부터 줄인다.
- 자동화 시나리오로 확인할 때는 "열자마자 보임", "그때 클릭해도 처리기가 불리지 않음", "준비 뒤 풀림" 세 가지를 나눠서 본다.
