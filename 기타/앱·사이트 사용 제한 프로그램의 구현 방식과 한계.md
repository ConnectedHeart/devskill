# 앱·사이트 사용 제한 프로그램의 구현 방식과 한계

> 분류: 기타 · 최근 갱신: 2026-10-14

## 한 줄 요약
자제용 사용 제한 도구는 Windows에서는 주기적 프로세스 감시, Android에서는 접근성 서비스로 만들 수 있지만, 사용자 권한으로 도는 한 "푸는 것을 번거롭게 하는" 수준이다.

## 내용
- **Windows**
  - 시간제한: 일정 주기(예: 5초)로 대상 프로세스가 떠 있는지 확인해 실행 시간을 누적하고, 하루 한도를 넘으면 예고 알림 후 종료한다. 자정에 초기화한다.
  - 실행 차단: 대상 프로세스가 뜨면 바로 종료한다. 검사 주기만큼은 떠 있다.
  - 다운로드 차단: 다운로드 자체를 막기는 어렵다. 다운로드 폴더에 이름 패턴(`*키워드*`)에 맞는 파일이 생기면 격리 폴더로 옮기거나 삭제하는 방식이 현실적이다. 파일명을 바꾸거나 다른 폴더에 받으면 걸리지 않는다.
  - 사이트 시간제한: 확장 프로그램 없이도 맨 앞 브라우저 창의 주소창 값을 읽어 도메인별 시간을 누적할 수 있다. 뒤에 깔린 탭은 세지 못하고, 전체 화면처럼 주소창이 숨겨지는 경우를 따로 처리해야 한다.
  - 관리자 권한 없이 사용자 계정으로 돌면 작업 관리자에서 끄거나 설정 파일을 고쳐 풀 수 있다. 남을 제한하려면 대상이 표준 계정이어야 의미가 있다.
  - **설정 파일 삭제로 초기화하는 우회 막기**: 같은 Windows 계정 권한으로 도는 프로그램이 쓸 수 있는 파일은 사용자도 지울 수 있다. 저장 형식(JSON·레지스트리)보다 "어디에, 어떤 권한으로 두느냐"가 보호 수준을 정한다. 같은 권한 안에서 쓸 만한 조합은 다음과 같다.
    - 실행 중에는 설정 파일 핸들을 열어 둔 채(다른 프로세스에 읽기만 공유) 유지한다. 탐색기 삭제·메모장 저장이 "다른 프로그램에서 열려 있음"으로 거부된다.
    - 저장할 때마다 같은 내용을 `HKCU\Software\<앱이름>`에도 쓴다. 비밀번호는 원문 대신 해시만 둔다.
    - 시작 시 파일과 레지스트리를 둘 다 읽어, 파일이 없거나 다르면 레지스트리 쪽으로 파일을 다시 만든다(레지스트리 우선 → 파일 손 편집이 무시됨). 최초 등록 창은 둘 다 없을 때만 띄운다.
    - 사용 시간 기록 파일도 같은 방식으로 보호하지 않으면 강제 종료 후 삭제로 오늘 사용량을 0으로 만들 수 있다.
    - 그래도 강제 종료 + 레지스트리 키 삭제, 시계 변경은 못 막는다. DPAPI 암호화 파일, 자격 증명 관리자, 숨김 폴더·대체 데이터 스트림(ADS), 사본 분산도 "찾기 어렵게" 할 뿐 같은 급이다. 실제로 못 지우게 하려면 관리자 권한 설치 + SYSTEM 서비스 + 관리자 전용 저장 위치(HKLM 등)로 가야 하고, 대상이 표준 계정이어야 한다.
  - C# 소스(`.cs`)는 Windows에 기본 포함된 컴파일러로 별도 설치 없이 exe로 만들 수 있어, 단일 파일 도구를 배포하기 쉽다. 서명이 없는 exe는 처음 실행할 때 SmartScreen 경고가 뜬다.
- **Android**
  - 다른 앱을 감시·제어하려면 접근성 서비스(AccessibilityService)를 쓴다. 맨 앞 앱의 패키지, 화면 클래스명, 뷰의 글자를 읽고 뒤로가기·홈 같은 전역 동작을 실행할 수 있다.
  - 다른 앱을 강제 종료할 수는 없다. 홈으로 내보내고 차단 화면을 덮는 방식이 된다.
  - 특정 앱의 특정 화면(예: 숏폼 탭)만 막으려면 화면 클래스명이나 선택된 탭의 글자로 식별해야 하는데, 대상 앱이 업데이트로 구조를 바꾸면 규칙을 다시 맞춰야 한다. 실기기에서 값을 확인할 수 있게 진단 로그 화면을 넣어 둔다.
  - 삭제 방지는 기기 관리자(Device Admin) 등록으로 시스템의 앱 삭제를 막고, 설정의 삭제·강제 중지·관리자 해제 화면이 열리면 접근성 서비스로 닫는 식으로 구현한다. 제조사마다 설정 화면 문구가 다르다.
  - 접근성 권한을 쓰는 앱은 스토어 심사가 까다로워 APK 직접 설치가 현실적이다. Android 13 이상에서는 직접 설치한 앱의 접근성 스위치가 막혀 있어 앱 정보의 "제한된 설정 허용"을 먼저 눌러야 한다.
  - 안전 모드로 부팅하면 접근성 서비스가 동작하지 않는다.
- **먼저 볼 기본 기능**: Windows의 Microsoft Family Safety, Android의 디지털 웰빙은 앱별 타이머와 브라우저 사이트 타이머를 이미 지원한다. 직접 만드는 쪽의 이점은 다운로드 파일 차단처럼 기본 기능에 없는 부분 정도다.

## 예시
다운로드 차단 패턴(파일명 기준, 대소문자 무시):

| 패턴 | 걸리는 파일 |
|---|---|
| `*game*` | 이름에 game이 들어간 모든 파일 |
| `*game*.exe` | 이름에 game이 들어간 exe만 |
| `*game*setup*` | game과 setup이 그 순서로 들어간 파일 |
| `*.torrent` | 모든 torrent 파일 |

## 주의할 점
- 한도 도달 시 강제 종료하면 저장하지 않은 내용이 사라진다. 5분·1분 전 예고를 넣는다.
- "바로 삭제" 방식은 휴지통을 거치지 않으므로, 넓은 패턴(`*a*`)은 엉뚱한 파일을 복구 불가능하게 지운다. 처음에는 격리로 써 본다.
- 탐색기 같은 필수 프로세스나 설정·전화·홈 화면 앱은 대상에 넣지 못하게 막아 둔다.
- 회사 PC에서는 보안 정책·반출 정책과 충돌할 수 있다.
