# 날짜 기준 전송 배치의 재전송 설계

> 분류: 기타 · 최근 갱신: 2026-10-27

## 한 줄 요약
"매일 전날 데이터를 파일로 내보내는 배치"에 관리자 재전송을 붙일 때는, 이력 테이블의 날짜가 "배치를 돈 날"인지 "담긴 데이터의 기준일"인지부터 맞춰야 하루 어긋남과 조용한 미전송이 사라진다.

## 내용
### 흔한 구조와 어긋나는 지점
- 배치가 D일 00:05에 D-1일 데이터를 보내고 이력에 `sent_date = now()`(= D일)를 남긴다. 재전송 화면은 날짜를 고르면 그 날짜의 이력 행에 N을 표시하고, 다음 배치는 N인 행의 날짜와 **같은 날 생성된** 데이터를 다시 보낸다.
- 그러면 D일 행은 D-1일 데이터를 보낸 기록인데, 재전송은 D일 데이터를 찾는다. 하루 어긋난다.
- 보낼 데이터가 0건이면 이력도 안 남기는 구조라면, "그 날짜 행이 없어서" 재전송 자체가 안 되는 날이 생긴다. 화면에는 "완료"로 뜨므로 아무도 모른다.
- 배치가 아예 안 돈 날(서버 점검)은 데이터도 안 나가고 행도 없다. 재전송이 가장 필요한 날인데 안 된다.

### 고치는 방법
1. 이력의 날짜를 "담긴 데이터의 기준일"로 기록한다(`now() - 1일`, 시각은 유지). 행 하나가 "이 날짜 데이터는 보냈다/다시 보내라"를 뜻하게 되어 재전송 조회와 의미가 맞는다.
2. 재전송 요청 시 고른 기간을 하루씩 돌며 행이 있으면 N으로 바꾸고 없으면 N 행을 새로 만든다. 그러면 0건이던 날과 배치가 안 돈 날도 재전송된다.
3. 서버에서도 기간을 검증한다(종료일은 어제까지, 시작≤종료, 최대 일수). 화면 검증만 믿으면 하루씩 도는 루프가 엉뚱한 범위를 돈다.
4. 전송 후 데이터 쪽 "보냄" 플래그를 실제로 되돌려 둔다. N으로만 바꾸고 Y로 돌리는 코드가 없으면 플래그 조건이 항상 참이 되어 "어제 수정됨" 같은 날짜 조건 하나에만 의존하게 되고, 하루 빠지면 영구 누락된다.

### 대안과 비교
| 방법 | 장점 | 단점 |
|---|---|---|
| 이력 날짜만 하루 당김 | 쿼리 한 줄 | 배치 안 돈 날은 여전히 불가 |
| 당김 + 없으면 행 추가 | 모든 경우 재전송, 새 테이블 없음 | 이력 테이블이 순수 실행 기록이 아니게 됨 |
| 재전송 시 즉시 파일 생성 | 다음 배치 안 기다림 | 다중 서버면 출력 폴더 공유 필요, 파일명 중복 |
| 재전송 요청 테이블 신설 | 이력·상태 관리 가능 | 사이트마다 DDL 반영 부담 |

### 설계 시 같이 볼 것
- 날짜를 DB(`CURDATE()`, `SYSDATE`)와 애플리케이션 양쪽에서 따로 계산하면 DB 서버 시간대가 다를 때(UTC 등) "어제"가 어긋난다. 대상 날짜를 한 곳에서 정해 모든 쿼리에 파라미터로 넘기는 편이 안전하다.
- 파일 끝의 건수 표시(`TOTAL_COUNT|n` 같은 트레일러 줄)가 신규분만 세는지 전체 행을 세는지는 수신 측 규격이 정한다. 전달만 하는 중계 에이전트의 문서에는 정의가 없으므로 받는 시스템 쪽에 물어야 한다. 재전송·수정분을 같은 파일에 넣기 시작했다면 규격을 다시 확인한다.
- 수신 측이 "문서ID + 생성일자"를 갱신 키로 쓴다면 재전송 시 생성일자를 절대 바꾸지 않는다. 바뀌면 별개 건으로 중복 등록된다. 날짜 형식(`YYYYMMDDHHMISS`)이 쿼리마다 다른 것도 같은 결과를 낸다.
- 이력 테이블을 운영자가 "배치가 돌았는지" 확인하는 용도로 보고 있었다면, 재전송용 행이 섞이기 시작한다는 점을 알린다.

## 핵심 코드

### 1) 재전송 요청: 기간을 하루씩 처리
```java
// 재전송 요청: 기간을 하루씩 처리
for (LocalDate d = start; !d.isAfter(end); d = d.plusDays(1)) {
    map.put("date", d.toString());
    if (dao.countHistoryByDate(map) > 0) dao.markResendByDate(map);
    else                                 dao.insertResendRow(map);   // 'N'
}
```

### 2) 기준일은 한 곳에서 정하고 서버에서 기간 검증 (Java 8)
```java
static final ZoneId ZONE = ZoneId.of("Asia/Seoul");                     // 바꿔야 할 곳: 업무 기준 시간대
static final DateTimeFormatter TS = DateTimeFormatter.ofPattern("yyyyMMddHHmmss");   // 형식도 한 곳에

static LocalDate baseDate(Clock clock) {                                 // 정기 배치의 기준일 = 어제
    return LocalDate.now(clock.withZone(ZONE)).minusDays(1);
}

static void validateRange(LocalDate start, LocalDate end, LocalDate today) {
    if (start == null || end == null)      throw new IllegalArgumentException("기간이 비었습니다.");
    if (start.isAfter(end))                throw new IllegalArgumentException("시작일이 종료일보다 늦습니다.");
    if (end.isAfter(today.minusDays(1)))   throw new IllegalArgumentException("종료일은 어제까지입니다.");
    if (ChronoUnit.DAYS.between(start, end) + 1 > 31)
                                           throw new IllegalArgumentException("한 번에 31일까지 재전송할 수 있습니다.");
}
```

### 3) 이력 SQL: 기준일로 기록, 없으면 N 행 추가
```sql
-- 정기 배치가 남기는 이력: 날짜는 "담긴 데이터의 기준일"(애플리케이션이 계산해 파라미터로)
INSERT INTO send_history (base_date, status, created_at) VALUES (?, 'Y', CURRENT_TIMESTAMP);

-- 재전송 요청: 먼저 UPDATE, 바뀐 행이 0건이면 INSERT
UPDATE send_history SET status = 'N' WHERE base_date = ?;
INSERT INTO send_history (base_date, status, created_at) VALUES (?, 'N', CURRENT_TIMESTAMP);
```
```java
// count 후 분기 대신 UPDATE 결과 건수로 분기하면 쿼리가 하나 준다
if (dao.markResendByDate(map) == 0) dao.insertResendRow(map);
```

### 4) 배치: 정기분 + 재전송분을 보내고 플래그 정리
```java
LocalDate base = baseDate(Clock.systemDefaultZone());
SortedSet<LocalDate> dates = new TreeSet<LocalDate>(dao.selectResendDates());   // status = 'N' 인 날짜
dates.add(base);                                                                  // 중복이면 한 번만
for (LocalDate d : dates) {
    List<Row> rows = dao.selectRowsCreatedOn(d);       // 생성일자가 d 인 데이터 (0건이어도 진행)
    writeFile(d, rows);                                // 생성일자 값은 원본 그대로 (수신 측 갱신 키)
    dao.markDataSent(d);                               // 데이터 쪽 "보냄" 플래그를 실제로 되돌린다
    dao.markHistorySent(d);                            // 이력 status = 'Y' (없으면 기준일로 INSERT)
}
```

## 주의할 점
- 반영 직후에는 "보낸 날" 기준의 옛 행과 "기준일" 기준의 새 행이 같은 날짜에 겹칠 수 있다. 날짜 목록으로만 쓰이면 무해하지만 건수를 세는 곳이 있으면 확인한다.
- 배치가 "보낼 게 없어 일찍 끝나는" 경로에서는 플래그 정리가 실행되지 않는다. N이 며칠 남아 매일 한 번 더 조회될 뿐이면 무해하지만, 의도를 주석으로 남긴다.
