# 목록과 건수를 따로 요청할 때 응답 순서 버그

> 분류: 기타 · 최근 갱신: 2026-11-02

## 한 줄 요약
목록과 전체 건수를 두 비동기 요청으로 나누면 응답 순서가 데이터 양에 따라 바뀌는데, 화면 코드가 "늘 건수가 먼저 온다"는 우연에 기대고 있으면 페이지 번호가 사라지거나 이전 건수로 동작하는 버그가 생긴다.

## 내용
### 왜 생기나
- 서버가 목록 요청에서도 건수를 계산하던 동안에는 목록 응답이 항상 늦게 와서, 건수 콜백이 먼저 끝난 뒤 목록 콜백이 화면을 마무리했다. 건수 계산을 목록 요청에서 빼 목록이 빨라지면 순서가 뒤집힐 수 있다.
- 데이터가 적은 개발 환경에서는 건수 쿼리가 더 빨라 여전히 건수가 먼저 오므로 증상이 안 보인다. 데이터가 많아 건수 계산이 느린 사이트에서만 나타난다.

### 대표 증상
1. **페이지 번호가 사라짐:** 건수 콜백이 공용 페이지 번호 함수를 부르는데, 그 함수가 영역을 먼저 비운 뒤 이 화면에 없는 전역 변수를 참조해 예외로 멈춘다. 목록 콜백이 이미 그려 둔 번호까지 지워진다. 화면별 전용 함수로 다시 그려야 한다.
2. **이전 건수로 동작:** 전역 "전체 건수" 변수는 건수 응답이 와야 바뀐다. 목록은 이미 새 조건인데 건수는 예전 값인 짧은 틈에 [출력] 같은 버튼을 누르면, 예전 건수가 출력 범위로 넘어가 앞부분만 출력된다(새 결과가 더 많을 때만 잘림).
3. **재사용한 요청 파라미터에 플래그가 남음:** "건수 생략" 플래그를 붙인 요청 파라미터를 다른 팝업이 그대로 재사용하면, 그 팝업은 건수 0을 받아 "결과 없음"으로 막힌다. 플래그를 붙이기 전의 파라미터를 따로 저장해 넘긴다.

### 고치는 방향
- 건수에 의존하는 동작은 건수 요청이 끝났는지(`readyState === 4`)를 확인하고, 아직이면 기존 "목록을 불러온 뒤 시도" 안내로 멈춘다.
- 응답 순서에 상관없이 마지막에 도착한 응답이 최종 상태를 그리게 한다(목록·건수 콜백 모두 "둘 다 왔으면 페이지 번호 갱신").

### 재현 요령
- 응답 순서는 브라우저 자동화의 요청 가로채기로 강제한다. 건수 요청만 몇 초 늦추면 "목록 먼저" 순서를 항상 재현할 수 있다. 세 경우(목록 먼저, 건수 먼저, 지연 없음)를 모두 돌린다.

## 핵심 코드
### 1) 건수 요청이 끝나기 전에는 건수 의존 동작을 막기
```javascript
function onPrintClick() {
  // 건수 요청이 진행 중이면 totalCount는 이전 조회 값
  if (!totalCount || (countXhr && countXhr.readyState !== 4)) {
    alert('목록을 불러온 뒤 다시 시도해 주세요.');
    return;
  }
  openPrintPopup(1, totalCount);
}
```

### 2) 플래그를 붙이기 전 파라미터를 따로 보관
```javascript
var baseParams = buildParams(filter);          // 팝업·출력이 재사용할 원본
listXhr  = post('/api/items', Object.assign({}, baseParams, { skipCount: 'Y' }));
countXhr = post('/api/items/count', baseParams);
```

### 3) Playwright로 건수 응답만 늦춰 순서 강제
```javascript
await page.route('**/api/items/count**', async route => {
  await new Promise(r => setTimeout(r, 2500));   // 목록 응답이 먼저 오게
  await route.continue();
});
await page.click('#searchBtn');
await expect(page.locator('#pager a')).toHaveCount(10);
```

## 주의할 점
- 서버 쪽 성능 수정(중복 카운트 제거)이 화면 버그를 "만든" 것이 아니라, 원래 있던 순서 의존을 드러낸 것이다. 성능 수정을 할 때 같은 응답을 쓰는 화면을 모두 열어 본다.
- 공용 콜백을 쓰는 화면이 여럿이면 화면 구분 값(전용 페이지 함수를 쓰는 화면인지)으로 분기하고, 구분 값이 없는 화면은 기존 동작을 유지한다.
