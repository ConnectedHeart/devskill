# 목록 화면에서 선택 행과 전역 변수가 어긋나는 버그

> 분류: 기타 · 최근 갱신: 2026-10-27

## 한 줄 요약
목록에서 "현재 선택한 항목의 ID"를 전역 변수에 저장해 두고 버튼에서 그 변수를 쓰면, 변수를 갱신하지 않는 선택 방식(체크박스, Ctrl/Shift 클릭)이 하나라도 있을 때 화면에 보이는 선택과 다른 항목이 처리된다.

## 내용
### 어떻게 생기나
- 오래된 목록 화면은 행을 클릭할 때 `currentId = 클릭한 행의 ID`처럼 전역 변수를 갱신하고, 버튼 핸들러는 그 변수를 서버로 보낸다.
- 선택을 바꾸는 경로가 여러 개인데 그중 일부만 변수를 갱신하면 어긋난다.
  - 행 클릭: 갱신함
  - 행 앞 체크박스 클릭: 선택 표시만 바꾸고 갱신하지 않음
  - Ctrl/Shift + 클릭(다중 선택): 클릭 콜백을 건너뛰어 갱신하지 않음
  - 키보드 이동, 목록 새로고침, 정렬·페이지 이동 등도 같은 누락이 생기기 쉽다
- 결과: 화면에는 A가 선택돼 있는데 변수에는 직전에 클릭했던 B가 남아 있어 B가 처리된다. 사용자에게는 "A를 보냈는데 B가 나갔다", "보낸 적 없는 B가 발송 목록에 있다"로 보인다.
- 서버는 받은 ID를 그대로 처리하므로 서버 로그만 봐서는 정상 요청으로 보인다. 원인은 화면에서 ID가 정해지는 방식에 있다.

### 행 안의 입력 컨트롤이 "선택된 행"을 고치는 경우
- 목록 각 행에 드롭다운(예: 결재·검토 같은 유형 선택)이 있고, 그 change 핸들러가 **드롭다운이 들어 있는 행이 아니라 목록의 현재 선택 행**을 고치도록 짜여 있으면 같은 종류의 어긋남이 생긴다.
- 다른 행이 선택된 채로 이 행의 드롭다운만 바꾸면, 화면에는 이 행 값이 바뀌어 보이지만 실제 데이터(행에 붙은 숨은 값)는 그대로이고 엉뚱한 선택 행의 데이터가 바뀐다. 선택 행이 없으면 핸들러가 바로 끝나 아무것도 바뀌지 않는다.
- 숨은 값이 그대로 저장·전송에 쓰이면 "화면에서 고른 값과 저장된 값이 다르다"는 결함이 된다. 재현은 "다른 행을 선택해 둔 채 드롭다운만 바꾼다"처럼 선택 행과 조작 행을 일부러 어긋나게 해야 나온다.
- 고칠 때는 핸들러가 이벤트 대상(`event.target`)이 속한 행을 찾아 그 행을 고치게 하거나, 처리 전에 그 행을 선택 행으로 맞춘다.

### 고치는 방법
- 버튼을 누르는 시점에 **선택된 행에서 ID를 다시 읽는다.** 전역 변수는 쓰지 않거나, 화면 표시용으로만 둔다.
- 선택이 0건·2건 이상일 때의 처리를 정한다. 단건 전용 기능이면 버튼을 숨기거나 안내 후 중단한다. "선택된 것 중 첫 번째"를 조용히 처리하면, 첫 번째는 마지막에 클릭한 행이 아니라 목록에서 가장 위의 행이어서 사용자의 기대와 다르다.
- 같은 패턴을 복사해 쓴 화면(관리자 화면, 변형 화면)이 있는지 함께 검색한다.

### 분석할 때의 요령
- "변수가 어디서 갱신되는가"를 전부 찾고, 그다음 "선택이 바뀌는 경로"를 전부 나열해 둘을 대조한다. 갱신 지점만 보고 "문서를 열 때만 갱신된다"처럼 단정하면 재현 경로를 틀리게 적는다.
- 재현 절차는 수정 전 코드에서 실제로 틀린 결과가 나오는 순서여야 한다. 그렇지 않으면 테스트가 수정 전에도 통과해 수정을 검증하지 못한다.
- 팝업을 고정된 창 이름으로 여는 화면은, 팝업을 띄운 채 다른 항목으로 다시 열면 새 창이 아니라 기존 창이 다시 로드된다. 팝업이 부모 창의 공용 변수에서 ID를 읽는 구조라면 여기서도 어긋날 수 있다.

## 핵심 코드

### 1) 전역 변수 대신 누르는 시점의 선택 행 읽기
```javascript
// 문제: 행 클릭 때 저장해 둔 값을 사용
function onSendClick() {
    openPopup(currentId);
}

// 수정: 누르는 시점의 선택 행에서 읽기
function onSendClick() {
    var rows = list.getSelectedRows();
    if (rows.length !== 1) {
        alert("한 건만 선택하세요.");
        return;
    }
    openPopup(rows[0].getAttribute("data-id"));
}
```

### 2) 라이브러리 없이 선택 행 ID 모으기
```javascript
// 행 클릭 선택(.selected)과 체크박스 선택을 모두 본다 — 바꿔야 할 곳: 선택 표시 클래스 이름
function getSelectedIds(table) {
    var ids = [];
    var rows = table.querySelectorAll("tbody tr");
    for (var k = 0; k < rows.length; k++) {
        var cb = rows[k].querySelector("input[type=checkbox]");
        if (rows[k].classList.contains("selected") || (cb && cb.checked)) {
            ids.push(rows[k].getAttribute("data-id"));
        }
    }
    return ids;
}
```

### 3) 선택 수에 맞춰 버튼 상태 갱신
```javascript
var table = document.getElementById("docList");
function refreshButtons() {
    var n = getSelectedIds(table).length;
    document.getElementById("btnSend").disabled = (n !== 1);      // 단건 전용 기능
    document.getElementById("btnDelete").disabled = (n === 0);    // 다건 가능 기능
}
// 행 클릭·체크박스·Ctrl/Shift 클릭·키보드 모두 이 두 이벤트로 모인다
// setTimeout: 목록 라이브러리의 선택 처리가 끝난 뒤에 읽기 위해
table.addEventListener("click", function () { setTimeout(refreshButtons, 0); });
table.addEventListener("keyup", function () { setTimeout(refreshButtons, 0); });
table.addEventListener("change", refreshButtons);
```

### 4) 팝업은 부모 변수 대신 주소로 ID 받기
```javascript
// 부모: 같은 창 이름으로 재사용돼도 주소가 바뀌므로 새 ID로 다시 로드된다
window.open("send.html?id=" + encodeURIComponent(id), "sendPopup", "width=600,height=500");

// 팝업: opener 의 전역 변수(opener.currentId)를 읽지 않는다
var id = new URLSearchParams(location.search).get("id");
```

### 5) 행 안 드롭다운은 자기 행을 고치기
```javascript
// 문제: 현재 선택 행을 고친다 — 다른 행이 선택돼 있으면 엉뚱한 행이 바뀐다
function onTypeChange() {
    var rows = list.getSelectedRows();
    if (rows.length === 0) return;          // 선택 행이 없으면 아무것도 안 바뀜
    rows[0].dataset.type = this.value;
}

// 수정: 이벤트가 난 드롭다운이 속한 행을 고친다
table.addEventListener("change", function (e) {
    if (!e.target.matches("select.type")) return;
    var row = e.target.closest("tr");
    row.dataset.type = e.target.value;      // 저장·전송에 쓰는 숨은 값도 함께 갱신
});
```

## 주의할 점
- 수정해도 이미 잘못 처리된 데이터는 그대로다. 정리가 필요한지 따로 확인한다.
- 체크박스가 일부 화면에만 붙는 경우 그 화면에서만 재현된다. "어떤 화면에서, 어떤 방식으로 선택했는지"를 신고자에게 물으면 원인을 빨리 좁힐 수 있다.
