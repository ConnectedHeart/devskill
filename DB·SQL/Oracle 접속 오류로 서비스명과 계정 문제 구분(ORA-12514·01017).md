# Oracle 접속 오류로 서비스명과 계정 문제 구분(ORA-12514·01017)

> 분류: DB·SQL · 최근 갱신: 2026-11-19

## 한 줄 요약
ORA-12514·12505는 리스너가 그 서비스명·SID를 모른다는 뜻이고, ORA-01017은 DB까지 닿았지만 계정 인증이 거부된 것이다. XE 18c 이상 같은 멀티테넌트 DB는 사용자 스키마가 PDB(`XEPDB1` 등)에 있어, CDB 서비스명(`XE`)으로 붙으면 같은 계정도 01017이 난다.

## 내용
- 접속 단계별 오류:

| 오류 | 의미 | 확인할 것 |
|---|---|---|
| 네트워크 오류(IO, connection refused) | 호스트·포트에 닿지 못함 | 주소, 포트, 방화벽 |
| ORA-12514 | 리스너가 그 **서비스명**을 모름 | `lsnrctl services`, 서비스명 철자 |
| ORA-12505 | 리스너가 그 **SID**를 모름 | SID 형식(`host:port:SID`)과 서비스 형식 구분 |
| ORA-01017 | DB가 접속은 받았지만 사용자/비밀번호 거부 | 계정이 그 컨테이너(PDB)에 있는지, 대소문자 |
| ORA-28000 | 계정 잠김 | 실패 시도 횟수 제한 |

- 멀티테넌트(CDB/PDB) 구조에서는 응용 계정이 보통 PDB에 만들어진다. CDB 루트 서비스(`XE`, `ORCLCDB`)로 접속하면 그 계정이 없어서 비밀번호가 맞아도 01017이 난다. PDB 서비스명(`XEPDB1`, `ORCLPDB1`)으로 접속해야 한다.
- 11g 이상은 비밀번호 대소문자를 구분한다.
- 같은 계정 이름이 MySQL과 Oracle에 있다고 같은 비밀번호라는 보장은 없다.

## 핵심 코드
```text
# JDBC thin URL 형식 - 서비스명은 // 와 /, SID는 :
jdbc:oracle:thin:@//db.example.com:1521/XEPDB1     ← 서비스명(PDB)
jdbc:oracle:thin:@db.example.com:1521:XE           ← SID
```

```sql
-- 접속된 뒤 지금 어느 컨테이너인지 확인
SELECT SYS_CONTEXT('USERENV','CON_NAME') AS con_name,
       SYS_CONTEXT('USERENV','SERVICE_NAME') AS service_name FROM dual;
-- (DBA) PDB 목록
SELECT name, open_mode FROM v$pdbs;
```

```bash
# 서버에서 리스너가 아는 서비스 목록
lsnrctl services
```

## 주의할 점
- 01017이 나면 같은 계정으로 여러 서비스명을 연달아 시도하지 않는다. 실패 횟수 제한(`FAILED_LOGIN_ATTEMPTS`)에 걸려 계정이 잠길 수 있다. 서비스명을 먼저 확인하고 한 번만 시도한다.
- 12514·12505가 나는 이름은 인증 시도까지 가지 않으므로 잠김과 무관하다. 이 차이로 "주소는 맞고 계정 단계에서 막혔다"를 가를 수 있다.
