# 화면 표시 이름과 검색 조건 컬럼 맞추기(경로 이름·띄어쓰기 무시)

> 분류: DB·SQL · 최근 갱신: 2026-11-20

## 한 줄 요약
목록에 보이는 이름(예: 「상위부서 팀명」 경로 이름)과 검색 조건이 비교하는 컬럼이 다르면 "보이는 대로 쳤는데 안 나오는" 문제가 생기므로, 표시용 컬럼을 OR로 더하고 기존 컬럼 비교는 남기며 띄어쓰기 없는 비교도 함께 둔다.

## 내용
- 흔한 원인: 화면 표시만 새 컬럼(경로 이름, 별칭 등)으로 바꾸고 검색 조건은 옛 이름 컬럼을 그대로 둔 경우. 화면에 「본부 영업팀」으로 보이는데 검색은 `name`(「영업팀」)만 비교하니 「본부 영업팀」으로 검색하면 0건이다.
- 고치는 방향
  1. 표시 컬럼 비교를 **OR로 더한다**. 표시 컬럼이 비어 있는 행(동기화 전 데이터)이 있으면 옛 컬럼 비교를 빼는 순간 그 행이 검색에서 사라지므로 기존 비교는 남긴다.
  2. 사용자가 띄어쓰기를 다르게 칠 수 있으므로 양쪽에서 공백을 지운 비교를 하나 더 둔다.
  3. 이력 테이블처럼 **기록 당시 이름을 저장한 테이블**은 지금 표시 이름이 없으니, 저장된 코드(부서 ID 등)로 현재 마스터를 찾아 비교한다(EXISTS 또는 서브쿼리).
  4. 검색 범위를 확인한다. 같은 조건 문자열이 다른 테이블(예: 사원과 부서 통합 검색)에도 붙는 구조면 그 테이블에 없는 컬럼을 붙여 SQL 오류가 난다. 해당 대상에만 적용한다.
- 같은 조건을 만드는 코드가 여러 곳이면 공통 함수 하나로 묶어 한 곳만 고쳐도 되게 한다. 화면 목록(어떤 검색 화면이 있는지)과 SQL 검색 결과를 대조해 빠진 곳을 찾는다.
- 경로 이름으로 비교하면 상위 이름으로 검색할 때 하위 항목까지 나와 건수가 늘 수 있다. 의도한 변화인지 알린다.
- 조건을 덧붙일 때 기존 `AND`/`OR` 괄호를 확인한다. 괄호 없이 `a AND b OR c`가 되면 앞 조건과 섞여 결과가 넓어진다. DB별 매퍼가 따로 있으면 한쪽만 괄호가 빠져 있는 경우도 있다.

## 핵심 코드
```sql
-- 마스터 테이블 검색: 옛 이름 + 표시 이름 + 공백 무시 비교 (MySQL)
SELECT dept_id, name, display_path
  FROM departments
 WHERE (   name         LIKE CONCAT('%', :kw, '%')
        OR display_path LIKE CONCAT('%', :kw, '%')
        OR REPLACE(display_path, ' ', '') LIKE CONCAT('%', REPLACE(:kw, ' ', ''), '%'));
```

```sql
-- 이력 테이블: 기록 당시 이름 + 저장된 코드로 찾은 현재 표시 이름 (Oracle)
SELECT h.*
  FROM login_history h
 WHERE (   h.dept_name LIKE '%' || :kw || '%'
        OR EXISTS (SELECT 1 FROM departments d
                    WHERE d.dept_id = h.dept_id
                      AND REPLACE(d.display_path, ' ', '') LIKE '%' || REPLACE(:kw, ' ', '') || '%'));
```

```java
// 조건 문자열을 코드에서 만드는 구조라면 공통 함수로 한 곳에서 (값은 반드시 바인딩/이스케이프)
static String nameCondition(SearchTarget target) {
    String base = "(name LIKE ? OR alt_name LIKE ?";
    if (target == SearchTarget.DEPARTMENT) {  // 부서만 검색할 때만 표시 컬럼 추가
        base += " OR display_path LIKE ? OR REPLACE(display_path,' ','') LIKE ?";
    }
    return base + ")";
}
```

```sql
-- 배포 전 점검: 표시 컬럼이 비어 있는 행 수
SELECT COUNT(*) FROM departments WHERE display_path IS NULL OR display_path = '';
```

## 주의할 점
- `REPLACE(...) LIKE '%...%'`는 인덱스를 타지 않는다. 마스터가 작으면 문제없지만 큰 이력 테이블에서는 다른 조건으로 먼저 좁힌 뒤 붙인다.
- 검색어를 문자열로 이어 붙이는 구조라면 따옴표·`%`·`_` 이스케이프를 확인한다.
- 표시 이름 변환이 사용자 언어 등 조건부로 일어나면(주 언어 사용자만 경로 이름 표시 등) 검색도 같은 조건을 따라야 결과가 일관된다. "화면에 경로가 안 나온다" 문의는 데이터 비어 있음·서버 버전·사용자 설정을 먼저 가른다.
- DB별 매퍼가 있으면 모든 DB 파일을 같은 의미로 고치고, 실행해 보지 못한 DB는 문법 대조만 했다고 남긴다.
