# PostgreSQL 개요와 MySQL·Oracle 문법 차이

> 분류: DB·SQL · 최근 갱신: 2026-10-27

## 한 줄 요약
PostgreSQL(줄여서 Postgres, PG)은 표준 SQL을 충실히 지원하는 오픈소스 관계형 데이터베이스로, Oracle 대체로 많이 검토된다. "postgre", "postgral"은 흔한 오기다.

## 내용
- 라이선스 비용이 없는 오픈소스 RDBMS.
- 트랜잭션, 외래키, 복잡한 조인·서브쿼리, 윈도우 함수, CTE(`WITH`)를 잘 지원해 Oracle과 쓰임새가 비슷하다.
- `jsonb`, 배열 타입, 전문 검색, 사용자 정의 함수, 확장(PostGIS 등)이 강점이다.
- 주요 클라우드(AWS, Azure, GCP)에서 관리형으로 제공된다.
- 여러 DB를 지원하는 애플리케이션이 DB별 SQL 파일(MyBatis/iBATIS sqlmap 등)을 두는 구조라면, PostgreSQL 지원은 모든 SQL 파일에 PG 버전을 추가하는 큰 작업이 된다.

## 핵심 코드
### 1) 문법 대조표
| 항목 | MySQL | Oracle | PostgreSQL |
|---|---|---|---|
| 문자열 합치기 | `CONCAT(a, b)` | `a \|\| b` | `a \|\| b` (`CONCAT`도 가능) |
| 행 수 제한 | `LIMIT 10` | `ROWNUM` / `FETCH FIRST` | `LIMIT 10` / `FETCH FIRST` |
| 자동 증가 | `AUTO_INCREMENT` | 시퀀스 / IDENTITY | `SERIAL` / IDENTITY / 시퀀스 |
| NULL 대체 | `IFNULL` | `NVL` | `COALESCE` |

### 2) 페이징 (21~30번째 행)
```sql
-- MySQL
SELECT * FROM orders ORDER BY id DESC LIMIT 10 OFFSET 20;
```
```sql
-- Oracle 12c 이상
SELECT * FROM orders ORDER BY id DESC OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
-- Oracle 11g 이하
SELECT * FROM (
  SELECT t.*, ROWNUM rn FROM (SELECT * FROM orders ORDER BY id DESC) t
   WHERE ROWNUM <= 30
) WHERE rn > 20;
```
```sql
-- PostgreSQL (FETCH FIRST 표준 구문도 가능)
SELECT * FROM orders ORDER BY id DESC LIMIT 10 OFFSET 20;
```

### 3) 자동 증가 키와 방금 넣은 키
```sql
-- MySQL
CREATE TABLE orders (id BIGINT AUTO_INCREMENT PRIMARY KEY, name VARCHAR(100));
INSERT INTO orders (name) VALUES ('a'); SELECT LAST_INSERT_ID();
```
```sql
-- Oracle 12c 이상
CREATE TABLE orders (id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, name VARCHAR2(100));
```
```sql
-- PostgreSQL 10 이상
CREATE TABLE orders (id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, name VARCHAR(100));
INSERT INTO orders (name) VALUES ('a') RETURNING id;
```

### 4) 문자열 연결·NULL 대체·현재 시각
```sql
-- MySQL
SELECT CONCAT(name, '-', code), IFNULL(memo, '-'), NOW() FROM orders;
-- Oracle (빈 문자열 ''은 NULL로 취급된다)
SELECT name || '-' || code, NVL(memo, '-'), SYSDATE FROM orders;
-- PostgreSQL
SELECT name || '-' || code, COALESCE(memo, '-'), NOW() FROM orders;
-- 세 DB 공통으로 쓰려면 COALESCE
```

### 5) 식별자 대소문자와 엄격한 형변환 (PostgreSQL)
```sql
CREATE TABLE "Orders" (id INT);   -- 따옴표로 만들면 이후에도 항상 "Orders"로 불러야 한다
SELECT * FROM Orders;             -- orders로 바뀌어 relation does not exist

-- code가 VARCHAR일 때
SELECT * FROM orders WHERE code = 100;       -- 오류: operator does not exist: character varying = integer
SELECT * FROM orders WHERE code = '100';     -- 값 쪽 타입을 맞춘다
SELECT * FROM orders WHERE code::int = 100;  -- 또는 명시 캐스트(인덱스는 못 탄다)
```

### 6) JDBC 연결
```xml
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <version>42.7.3</version>   <!-- 42.x는 Java 8 지원 -->
</dependency>
```
```properties
jdbc.driverClassName=org.postgresql.Driver
jdbc.url=jdbc:postgresql://<서버 주소>:5432/<DB 이름>
```

## 주의할 점
- PostgreSQL은 따옴표 없는 식별자를 소문자로 바꾼다. 대문자 테이블명을 쓰던 스키마를 옮길 때 주의한다.
- 문자열과 숫자 비교 등 암묵적 형변환이 MySQL보다 엄격하다.
