# 하네스 엔지니어링 개념

> 분류: Claude Code · 최근 갱신: 2026-10-20

## 한 줄 요약
하네스(harness)는 AI 에이전트에서 LLM 모델을 뺀 나머지 전부다. 시스템 프롬프트, 도구, 루프, 컨텍스트, 메모리, 권한, 검증 장치가 여기에 들어가며, 같은 모델이라도 하네스에 따라 결과가 크게 달라진다.

## 내용
### 정의와 의미
- 원래 "말의 마구"나 "테스트 하네스(테스트를 돌리는 틀)"에서 온 말이다. 모델이 엔진이라면 하네스는 차체·계기판·브레이크·안전벨트에 해당한다.
- 모델은 벤더가 만들지만, 애플리케이션 개발자가 실제로 손댈 수 있는 것은 하네스다. 코딩 벤치마크에서도 모델은 그대로 두고 스캐폴드만 바꿔 점수가 크게 달라지는 사례가 많다.
- 관심사는 다음 순서로 넓어졌다.
  - 프롬프트 엔지니어링: 지시문 한 번을 잘 쓴다.
  - 컨텍스트 엔지니어링: 매 턴 모델에게 무엇을 보여줄지 설계한다.
  - 하네스 엔지니어링: 모델을 둘러싼 시스템 전체를 설계한다.
- Claude Code 같은 코딩 에이전트가 대표적인 하네스다. 프로젝트 지침 파일, 훅, 권한 모드, 메모리, 스킬이 모두 그 구성품이다.

### 구성 요소
- **에이전트 루프**: 모델 호출 → 도구 호출 요청 파싱 → 도구 실행 → 결과를 대화에 붙여 다시 호출. 이 과정을 종료 조건까지 반복한다. 최대 턴 수, 토큰 예산, 사람이 끼어드는 지점을 정한다.
- **도구 설계**: 도구는 적고 서로 겹치지 않게 만든다. 설명에는 "언제 쓰지 말라"까지 적는다. 오류 메시지는 모델이 다음에 무엇을 해야 하는지 알 수 있게 쓴다.
- **컨텍스트 관리**: 모든 것을 시스템 프롬프트에 넣지 않는다. 필요할 때 파일을 읽히고(just-in-time), 긴 대화는 요약(컴팩션)하고, 큰 탐색은 서브에이전트에 맡겨 결론만 받는다.
- **메모리·상태 영속화**: 컨텍스트는 사라지므로 작업 목록, 진행 로그, 커밋을 파일로 남긴다. 다음 세션은 파일만 읽고 이어갈 수 있어야 한다.
- **가드레일**: 쓰기 범위, 샌드박스, 위험 명령 차단, 비용 상한, 중단 조건을 둔다. 모델을 믿기보다 구조로 막는다.
- **피드백 루프**: 테스트, 컴파일, 린터, 타입 검사, 스크린샷처럼 결과를 기계로 판정하는 장치. 에이전트가 자기 결과를 확인할 수단이 있을 때 품질이 가장 크게 오른다.
- **환경 설계**: 저장소 자체를 에이전트가 일하기 좋게 만든다. 지침 파일(AGENTS.md 등), 분명한 빌드·테스트 명령, 일관된 구조가 여기에 해당한다.

### 사용자 규칙과 AI 관리 문서 나누기
- 에이전트가 작업하면서 지침 파일을 스스로 고치게 두면, 사람이 정한 규칙이 언제 어떻게 바뀌었는지 놓치기 쉽다. 소유자별로 나눈다.
  - **사용자 규칙**: AGENTS.md, CLAUDE.md, 스킬 SKILL.md. 사람이 지시할 때만 고친다. 권한 설정에서 이 경로에 대한 쓰기(Edit·Write와 셸 명령)를 `ask`로 두면 구조적으로 승인 창이 뜬다.
  - **AI 협업 문서**: 일반 폴더(예: `<AI 문서 폴더>/`)에 운영 요령, 모듈별 프로젝트 지식 노트, 규칙 변경 제안 파일을 두고 AI가 자유롭게 고친다. 일반 폴더라 다른 에이전트(Codex 등)도 AGENTS.md의 안내를 따라 읽을 수 있다.
  - 둘이 충돌하면 사용자 규칙이 우선한다. 규칙을 바꾸는 편이 낫다고 판단하면 AI는 제안 파일에만 적고 보고한다.
- **변경 감지**: 사람이 확인한 시점의 지침 파일 사본을 기준본으로 두고, 하루 첫 프롬프트 훅에서 기준본과 다른 파일을 요약 보고한다. 사람이 확인하면 기준본을 갱신하고, 모르는 변경이면 기준본으로 되돌린다. AI가 직접 바꾼 것도 AI가 스스로 확인 처리하지 않는다.
- 지식 노트는 작업 로그를 옮긴 것이라 시간이 지나면 코드와 어긋난다. 노트마다 "기록 당시 기준, 고치기 전에 다시 확인"을 적어 둔다.

## 예시
```
<저장소>/
  AGENTS.md                      # 매 세션 지킬 규칙 (짧게)
  CLAUDE.md                      # @AGENTS.md 한 줄로 포함
  .claude/skills/verify/SKILL.md # 필요할 때만 읽는 절차 (검증)
  .claude/skills/<작업>/SKILL.md # 양식·체크리스트
```

## 주의할 점
- 지침 파일이 길어지면 매 세션 비용이 늘고 핵심 규칙이 묻힌다. 항상 지킬 규칙만 남기고, 가끔 쓰는 절차는 스킬로 뺀다.
- 검증 수단이 없는 작업(사람만 확인할 수 있는 화면 동작 등)은, 에이전트가 사람에게 넘길 재현 절차 양식을 하네스에 미리 정해 둔다.
