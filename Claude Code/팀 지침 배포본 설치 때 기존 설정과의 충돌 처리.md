# 팀 지침 배포본 설치 때 기존 설정과의 충돌 처리

> 분류: Claude Code · 최근 갱신: 2026-11-11

## 한 줄 요약
팀 공통 AGENTS.md·CLAUDE.md·스킬·settings.json을 배포본으로 나눠 줄 때는, 받는 사람 저장소에 이미 있는 파일과의 충돌 규칙(규칙 파일은 선택 덮어쓰기+백업, settings.json은 항목만 합치기, 개인 파일은 보존)을 설치 절차에 적고, 빈 저장소와 기존 파일이 든 시험 저장소 두 경우로 실제 설치를 시험한다.

## 내용
### 배포본에서 뺄 것
- 내 PC에서만 도는 것: 개인 래퍼·경로·포트·환경 변수, 내 작업 방식에서 나온 폴더 규칙, "자동 메모리가 맡는다"처럼 도구·설정에 따라 없는 기능에 기대는 문장.
- 관리 주체·전달 방법이 없는 흐름(예: "후보를 관리자에게 넘긴다"만 적힌 것)은 받은 사람에게 동작하지 않는다. 담당자·방법을 적거나 뺀다.

### 파일 종류별 충돌 처리
| 대상 | 처리 | 이유 |
|---|---|---|
| `AGENTS.md`·`CLAUDE.md`·같은 이름 스킬 | 차이를 보여 주고 덮어쓸지 선택. 덮어쓰기 전 자동 백업 | 줄 단위 병합은 의미가 깨짐. 보통 `.gitignore` 대상이라 git으로 복구 불가 |
| `.claude/settings.json` | 통째로 바꾸지 않고 `permissions.deny`·`ask`의 없는 항목만 덧붙임 | 개인 `model`·`env`·`allow`·`hooks` 보존 |
| 팀 함정 목록(`rules/team/*`) | 업데이트 때 묻지 않고 교체 | 고정 목록. 개인 메모는 다른 파일 이름으로 |
| 이름이 다른 개인 파일(개인 스킬 등) | 그대로 둠 | |
| 예전 배포본이 남긴 폴더 | 내용을 요약해 보여 준 뒤 삭제 여부 질문 | 쓸 만한 메모가 같이 사라짐 |

- 권한이 겹칠 때: Claude Code는 deny → ask → allow 순으로 먼저 걸리는 규칙을 따른다. 개인이 `allow`로 풀어도 배포본의 `ask`·`deny`가 이긴다(어느 설정 파일에 있든 deny는 막음).
- 개인 전역 지침(`~/.claude/CLAUDE.md`)과 저장소 지침이 다르면 정해진 우선순위가 없고 모델이 상황에 따라 판단한다. 권한 규칙으로 막은 것은 지침으로 풀 수 없다.

### 설치 절차에 넣을 판정 규칙
- 설치/업데이트 판정: 요청 문구와 관계없이 대상 저장소에 `AGENTS.md`가 있으면 업데이트, 없으면 처음 설치.
- 후보 저장소가 많을 때: 질문 창 선택지(4개 한도)에는 최근 커밋 시각 순으로 넣고, 나머지는 질문 문장에 `경로 [브랜치, 설치 여부]`로 적어 직접 입력받는다. 같은 날짜면 시각까지 비교한다.
- 질문 언어·"선호 없음" 답의 기본값(예: 브랜치로 판단)을 명시한다. 대화 없는 실행(`claude -p`, 다른 에이전트)에는 질문 도구가 없으므로 채팅 질문으로 대신한다.
- 이미 git이 추적 중인 파일은 `.gitignore`에 넣어도 계속 추적된다. `git ls-files`로 찾아 알려 주되, `git rm --cached`를 커밋해 push하면 **다른 사람 작업 폴더에서도 그 파일이 지워지므로** 실행은 사용자가 정한다. 대상은 배포본에 있는 파일로만 좁힌다.
- settings.json 합치기는 없는 항목만 뒤에 덧붙이고 UTF-8(BOM 없음)으로 저장한다. Windows PowerShell 5.1의 `ConvertTo-Json`은 들여쓰기 모양을 크게 바꾸므로 7을 우선 쓴다.

### 시험 방법
- 실제 저장소 대신 시험 저장소 두 종류: ① 하네스 파일이 하나도 없는 빈 저장소 ② 옛 버전 `AGENTS.md`, 다른 키가 섞인 `settings.json`, 개인 스킬, 예전 폴더를 일부러 넣은 저장소.
- 설치 후 확인: 자리표시자(`{{…}}`)가 남지 않았는지, JSON이 파싱되는지, import 경로가 실제 파일을 가리키는지, 새 세션에서 "이 저장소 작업 규칙 요약해줘"로 규칙이 로드되는지.
- 고친 절차는 다시 설치해 봐야 확인된다. 시험이 끝나면 시험 폴더를 지운다.

## 핵심 코드
### 1) settings.json 권한 항목만 합치기 (Node.js)
```javascript
const fs = require("fs");
const mine = JSON.parse(fs.readFileSync(".claude/settings.json", "utf8"));
const team = JSON.parse(fs.readFileSync("dist/.claude/settings.json", "utf8"));
mine.permissions = mine.permissions || {};
for (const key of ["deny", "ask"]) {
  const cur = mine.permissions[key] || [];
  for (const rule of team.permissions[key] || []) if (!cur.includes(rule)) cur.push(rule);   // 없는 것만
  mine.permissions[key] = cur;
}
fs.writeFileSync(".claude/settings.json", JSON.stringify(mine, null, 2) + "\n", "utf8");     // BOM 없음
```

### 2) 덮어쓰기 전 백업과 추적 중 파일 찾기
```bash
ts=$(date +%Y%m%d-%H%M%S); mkdir -p ".harness-backup/$ts"
cp --parents AGENTS.md CLAUDE.md .claude/skills/verify/SKILL.md ".harness-backup/$ts/" 2>/dev/null
git ls-files -- AGENTS.md CLAUDE.md .claude/settings.json ".claude/**/*.md"   # 이미 추적 중인 것
# 추적 해제는 사용자 결정 후에만: git rm --cached <파일>
```

### 3) 받는 사람에게 줄 설치 안내
```text
1. 배포본 폴더를 풀고 그 폴더를 작업 폴더로 Claude Code를 연다.
2. "하네스 설치해줘" → 저장소·표준/사이트·덮어쓰기·.gitignore 질문에 답한다.
3. 각 저장소에서 새 세션을 열고 "이 저장소 작업 규칙 요약해줘"로 로드를 확인한다.
4. 새 배포본은 같은 방법으로 "하네스 업데이트해줘".
```

## 주의할 점
- 받은 사람이 직접 보탠 규칙은 덮어쓰기로 사라진다. 백업 경로를 보고에 적는다.
- 배포본에 회사 내부 주소·계정·비밀값 흔적이 남지 않았는지 배포 전에 검색한다.
