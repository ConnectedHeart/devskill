# 권한 규칙으로 특정 명령만 자동 허용하기

> 분류: Claude Code · 최근 갱신: 2026-10-27

## 한 줄 요약
넓은 `ask` 규칙이 걸린 명령 중 일부만 승인 없이 돌리고 싶으면, 그 일부를 입력을 검사하는 전용 스크립트로 감싸고 그 스크립트만 `allow`에 넣는다.

## 내용
- **ask가 allow보다 우선한다**: 어떤 명령에 `ask` 규칙과 `allow` 규칙이 함께 걸리면 승인 창이 뜬다. 그래서 `ask: Bash(run-remote.ps1 *)`가 있는 상태에서 일부 인자만 `allow`로 풀 수는 없다.
- **"항상 허용"은 명령 문자열이 같을 때만 통한다**: 승인 창에서 항상 허용을 눌러도 다음 실행의 인자(파일 이름 등)가 다르면 다시 묻는다. 그래서 허용 항목이 설정 파일에 계속 쌓인다.
- **전용 래퍼 방식**
  1. 자주 쓰고 안전한 기능만 골라 각각 별도 스크립트로 만든다. 예: 로컬 화면 테스트 실행, `git fetch`.
  2. 스크립트는 실행 전에 입력을 검사한다. 정해진 폴더 밖 파일, 정해진 대상(localhost 등) 밖으로 접속하는 테스트, 허용 저장소 밖 경로를 거부한다.
  3. 그 스크립트만 `allow`에 넣는다. 기존의 넓은 `ask` 규칙은 그대로 둔다.
  4. 거부 동작을 하나씩 시험해, 막혀야 할 입력이 실제로 실행 전에 막히는지 확인한다.
- **무엇을 자동 허용할지 고르는 기준**: 실행 기록을 세어 빈도가 높고 데이터를 바꾸지 않는 것부터. push, 임의 명령, 개인정보를 조회할 수 있는 DB 조회는 계속 묻게 둔다.
- **자동 허용을 거둘 때 주의**: 래퍼의 `allow` 규칙만 지우면, 그 래퍼가 원래의 `ask` 패턴(`run-remote.ps1 *`)에 걸리지 않는 이름이라 오히려 아무 규칙에도 안 걸려 묻지 않고 실행될 수 있다. 자동 허용을 그만둘 기능은 래퍼 스크립트 자체를 지운다.
- **지침 파일 보호**: 사람이 정한 지침 파일(AGENTS.md 등)에 Edit·Write `ask` 규칙을 두면 에이전트가 고칠 때마다 승인 창이 뜬다. 다만 셸 명령은 문자열에 파일명이 직접 나올 때만 걸리므로 와일드카드·변수·별도 스크립트로는 우회될 수 있다. 사후 변경 감지를 함께 두거나, 아예 막으려면 `deny`를 쓴다.

## 핵심 코드
### 1) 넓은 ask는 두고 전용 래퍼만 allow
```json
{
  "permissions": {
    "ask":   ["Bash(powershell -File ~/tools/run-remote.ps1 *)"],
    "allow": [
      "Bash(powershell -File ~/tools/remote-scenario.ps1 -Name *)",
      "Bash(powershell -File ~/tools/remote-gitfetch.ps1)"
    ]
  }
}
```
인자가 없는 래퍼는 ` *` 없이 정확히 일치하는 규칙으로 둔다.

### 2) 입력을 검사하는 래퍼 (~/tools/remote-scenario.ps1)
```powershell
param([Parameter(Mandatory)][string]$Name)
$dir = Join-Path $HOME 'tools\scenarios'                         # 허용 폴더
if ($Name -notmatch '^[A-Za-z0-9_-]+\.js$') { 'FAIL invalid name'; exit 2 }   # ..\ 같은 경로 차단
$path = Join-Path $dir $Name
if (-not (Test-Path $path)) { 'FAIL not found'; exit 2 }

# 스크립트 안의 접속 주소가 localhost 뿐인지 확인
$src  = Get-Content $path -Raw
$urls = [regex]::Matches($src, 'https?://[^\s''"`)]+') | ForEach-Object Value
$bad  = $urls | Where-Object { $_ -notmatch '^https?://(localhost|127\.0\.0\.1)(:\d+)?(/|$)' }
if ($bad) { "FAIL external url: $($bad -join ', ')"; exit 2 }

node $path
"OK exit=$LASTEXITCODE"
```

### 3) 거부 동작 시험
```powershell
powershell -File ~/tools/remote-scenario.ps1 -Name '..\secret.js'    # FAIL invalid name
powershell -File ~/tools/remote-scenario.ps1 -Name 'nofile.js'       # FAIL not found
powershell -File ~/tools/remote-scenario.ps1 -Name 'external.js'     # 외부 주소가 든 시험 파일 → FAIL external url
powershell -File ~/tools/remote-scenario.ps1 -Name 'smoke.js'        # 정상 → OK exit=0
```

### 4) 자주 쓰는 명령 세기 (대화 기록에서)
```bash
# 대화 기록(~/.claude/projects/<프로젝트>/*.jsonl)에서 셸 명령 문자열만 뽑아 빈도순
grep -ohE '"command":"[^"]{1,120}' ~/.claude/projects/<프로젝트>/*.jsonl \
  | sed 's/^"command":"//' | sort | uniq -c | sort -rn | head -30
```

### 5) 지침 파일 보호: 편집은 묻고, 아예 막을 것은 deny
```json
{
  "permissions": {
    "ask":  ["Edit(./AGENTS.md)", "Edit(./CLAUDE.md)", "Edit(./.claude/skills/**)"],
    "deny": ["Edit(./.claude/settings.json)"]
  }
}
```
`Edit` 규칙은 파일을 고치는 내장 도구 전체(Edit·Write 등)에 적용된다. 셸 명령으로 쓰는 경우는 막지 못하므로 사후 변경 감지를 함께 둔다.

## 주의할 점
- 래퍼가 허용한 스크립트 안에 데이터를 바꾸는 단계를 넣으면 그대로 묻지 않고 실행된다. 스크립트 작성 규칙(저장·발송 단계는 사전 확인)을 따로 둔다.
- 지침 문서에 "승인 창으로 승인받는다"고 적혀 있으면 자동 허용과 맞지 않게 된다. 설정을 바꾸면 문서도 함께 맞춘다.
