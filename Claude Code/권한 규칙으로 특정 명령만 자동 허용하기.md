# 권한 규칙으로 특정 명령만 자동 허용하기

> 분류: Claude Code · 최근 갱신: 2026-10-21

## 한 줄 요약
넓은 `ask` 규칙이 걸린 명령 중 일부만 승인 없이 돌리고 싶으면, 그 일부를 입력을 검사하는 전용 스크립트로 감싸고 그 스크립트만 `allow`에 넣는다.

## 내용
- **ask가 allow보다 우선한다**: 어떤 명령에 `ask` 규칙과 `allow` 규칙이 함께 걸리면 승인 창이 뜬다. 그래서 `ask: Bash(run-remote.ps1 *)`가 있는 상태에서 일부 인자만 `allow`로 풀 수는 없다.
- **"항상 허용"은 명령 문자열이 같을 때만 통한다**: 승인 창에서 항상 허용을 눌러도 다음 실행의 인자(파일 이름 등)가 다르면 다시 묻는다. 그래서 허용 항목이 설정 파일에 계속 쌓인다.
- **전용 래퍼 방식**
  1. 자주 쓰고 안전한 기능만 골라 각각 별도 스크립트로 만든다. 예: 로컬 화면 테스트 실행, `git fetch`.
  2. 스크립트는 실행 전에 입력을 검사한다. 정해진 폴더 밖 파일, 정해진 대상(localhost 등) 밖으로 접속하는 테스트, 허용 저장소 밖 경로를 거부한다.
  3. 그 스크립트만 `allow`에 넣는다. 기존의 넓은 `ask` 규칙은 그대로 둔다.
  4. 거부 동작을 하나씩 시험해, 막혀야 할 입력이 실제로 실행 전에 막히는지 확인한다.
- **무엇을 자동 허용할지 고르는 기준**: 실행 기록을 세어 빈도가 높고 데이터를 바꾸지 않는 것부터. push, 임의 명령, 개인정보를 조회할 수 있는 DB 조회는 계속 묻게 둔다.
- **자동 허용을 거둘 때 주의**: 래퍼의 `allow` 규칙만 지우면, 그 래퍼가 원래의 `ask` 패턴(`run-remote.ps1 *`)에 걸리지 않는 이름이라 오히려 아무 규칙에도 안 걸려 묻지 않고 실행될 수 있다. 자동 허용을 그만둘 기능은 래퍼 스크립트 자체를 지운다.
- **지침 파일 보호**: 사람이 정한 지침 파일(AGENTS.md 등)에 Edit·Write `ask` 규칙을 두면 에이전트가 고칠 때마다 승인 창이 뜬다. 다만 셸 명령은 문자열에 파일명이 직접 나올 때만 걸리므로 와일드카드·변수·별도 스크립트로는 우회될 수 있다. 사후 변경 감지를 함께 두거나, 아예 막으려면 `deny`를 쓴다.

## 예시
```json
{
  "permissions": {
    "ask":   ["Bash(powershell -File ~/tools/run-remote.ps1 *)"],
    "allow": [
      "Bash(powershell -File ~/tools/remote-scenario.ps1 -Name *)",
      "Bash(powershell -File ~/tools/remote-gitfetch.ps1)"
    ]
  }
}
```

## 주의할 점
- 래퍼가 허용한 스크립트 안에 데이터를 바꾸는 단계를 넣으면 그대로 묻지 않고 실행된다. 스크립트 작성 규칙(저장·발송 단계는 사전 확인)을 따로 둔다.
- 지침 문서에 "승인 창으로 승인받는다"고 적혀 있으면 자동 허용과 맞지 않게 된다. 설정을 바꾸면 문서도 함께 맞춘다.
