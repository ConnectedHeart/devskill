# 지침과 지식 노트를 로딩 시점에 맞게 배치하기

> 분류: Claude Code · 최근 갱신: 2026-11-12

## 한 줄 요약
Claude Code는 기능마다 컨텍스트에 올라가는 시점이 다르다. 모듈별 지식 노트는 `.claude/rules/` 아래에 `paths:`를 지정해 두면 그 경로 파일을 열 때만 자동으로 로드되므로, "작업 전에 노트를 다 읽어라" 같은 지시보다 싸고 확실하다.

## 내용
### 기능별 로딩 시점
| 위치 | 언제 로드되나 | 알맞은 용도 |
|---|---|---|
| CLAUDE.md (+ `@import`) | 매 세션 시작, 전체 | 매번 지킬 규칙. 200줄 이하 권장. import로 나눠도 비용은 같다 |
| `.claude/rules/*.md` (`paths` 없음) | 매 세션 시작 | CLAUDE.md를 주제별로 나눈 것 |
| `.claude/rules/*.md` (`paths:` 지정) | 그 경로의 파일을 Read/Write/Edit할 때만 | 특정 디렉터리·모듈에만 해당하는 지식 |
| 자동 메모리(MEMORY.md) | 매 세션, 앞부분만 | 코드로 알 수 없는 것만. 지침 파일에 이미 있는 내용은 넣지 않는다 |
| Skill | 설명만 항상, 본문은 쓸 때 | 절차, 양식, 체크리스트 |
| Hook·권한 설정 | 이벤트 때 외부에서 실행 | 반드시 지켜야 하는 규칙(지침 문구는 보장이 아니라 요청이다) |
| 서브에이전트 | 띄울 때, 별도 컨텍스트 | 많이 읽고 결론만 받아야 할 때 |

### 경로 지정 노트
- 파일 맨 위 frontmatter에 `paths:`로 글롭 패턴을 적는다. 그 패턴에 맞는 파일을 열거나 고치면 노트가 함께 붙는다. 관련 없는 작업에서는 컨텍스트를 쓰지 않는다.
- 하위 폴더(`.claude/rules/<이름>/`)로 묶어도 된다. 사람이 정한 규칙과 AI가 관리하는 노트를 폴더로 구분하기 좋다.
- 같은 세션에서 같은 노트는 처음 한 번만 붙는다. 경로가 겹치게 잡으면 한 파일이 노트 여러 개를 함께 부른다.
- rules 폴더는 세션 시작 때 찾는다. 노트를 새로 만든 그 세션에서는 자동 로드가 안 될 수 있으니 확인은 새 세션에서 한다.
- 다른 저장소에서 연 세션에서는 이 저장소의 rules가 자동으로 붙지 않는다. 다른 에이전트 도구(Codex 등)도 이 폴더를 자동으로 읽지 않는다.

### 무엇을 남기나
- **남긴다**: 사람의 결정과 이유, 외부 시스템 동작, 함정(코드만 보면 오해하는 것), 환경·테스트 특이점.
- **남기지 않는다**: 코드 구조 설명(코드를 직접 읽는 게 더 정확), 수정 경위(git log에 있음), 다른 문서에 이미 있는 규칙.
- 틀린 노트는 노트가 없는 것보다 나쁘다. 없으면 코드를 보지만, 있으면 믿고 따른다.
- 새 사실이 옛 줄과 부딪히면 덧붙이지 말고 옛 줄을 고치거나 지운다. 쓰기 전에 같은 키워드를 검색한다.
- 위치는 줄 번호 대신 `클래스.메소드`처럼 적는다. 줄 번호는 코드가 바뀌면 바로 틀어진다.
- 노트에 위치 표시가 있으면 "기록일 이후 그 파일이 바뀐 항목"을 스크립트로 골라 의심 항목으로 볼 수 있다.

### 늘어난 지침 분량 줄이기
지침이 쌓이면 매 세션 기본으로 읽히는 분량이 수만 자가 된다. 줄일 때는 파일별 글자 수부터 재고, "언제 필요한가"로 나눈다.
- **작업 종류별 합계를 잰다**: 매 세션 기본(CLAUDE.md·항상 로드 rules·메모리 목차), 자주 쓰는 스킬을 더한 경우(예: 검증 스킬), 가장 무거운 작업(여러 스킬이 겹치는 경우)을 따로 센다. 효과도 이 단위로 비교한다.
- **조건부 내용을 떼어 낸다**: 스킬 본문 중 일부 상황에서만 필요한 긴 설명(서버 띄우기·내부망 절차 등)은 같은 스킬 폴더의 별도 파일로 옮기고, 본문에는 "○○할 때 읽는다" 한 줄만 남긴다. 그 상황이 없는 작업은 그만큼 덜 읽는다. 반대로 그 상황이 늘 있는 작업은 효과가 거의 없다.
- **특정 사이트·하위 프로젝트 전용 내용**은 항상 로드되는 노트에서 빼서 필요할 때 읽는 노트로 옮기고, 한 줄 안내만 남긴다.
- **중복을 합친다**: 같은 규칙이 여러 파일에 있으면 한 곳만 원본으로 두고 나머지는 가리킨다. 날짜별 변경 이력 문장은 지운다.
- **메모리 목차 정리**: 날짜가 지난 할 일 줄은 한 줄 모음으로 합치고, 끝난 항목 파일은 지운다.
- **지워서는 안 되는 것**: 다른 에이전트 도구처럼 권한 차단이 없는 환경에서는 금지 문장 하나가 유일한 방어일 수 있다. 그런 문장은 중복이어도 남긴다.
- **점검할 때 충돌도 찾는다**: 규칙 파일·스킬·메모리가 같은 상황을 다르게 말하는 곳(승인 여부, 예외 범위 등)을 표로 모아 사람에게 결정받고 모든 곳을 같은 문장으로 맞춘다.
- 실제 사례에서 이 방식으로 매 세션 기본 분량이 약 20%, 컴파일만 하는 작업(기본+검증 스킬)은 약 27% 줄었다. 새 세션에서 규칙이 제대로 동작하는지는 따로 확인해야 한다.

## 핵심 코드
### 1) 배치 구조
```text
<저장소>/
  CLAUDE.md                         # 매 세션 규칙 (짧게) + @import
  .claude/rules/common.md           # paths 없음: 매 세션 로드
  .claude/rules/ai/billing.md       # paths 지정: 해당 파일을 열 때만 로드
  .claude/skills/<작업>/SKILL.md    # 설명만 항상, 본문은 쓸 때
```

### 2) 경로 지정 노트 (.claude/rules/ai/billing.md)
```markdown
---
paths:
  - "src/main/java/com/example/billing/**"
  - "src/main/webapp/js/billing/**"
---
# billing — 코드로 알 수 없는 것
- [결정] 환불 재시도는 1회만, 2회째는 수동 처리 (2026-10-20, 담당자 결정)
- [함정] 외부 PG 응답의 금액은 문자열로 온다. BillingService.parse에서 변환
```

### 3) CLAUDE.md에서 나눈 파일 포함
```markdown
# <프로젝트>

@AGENTS.md
@docs/build-commands.md
```

### 4) 패턴마다 걸리는 파일 수 세기
```bash
# 로드 확인: 노트마다 패턴에 걸리는 파일이 실제로 있는지 세어 본다(0이면 아무것도 로드되지 않음)
find .claude/rules -name '*.md' | while read -r f; do
  sed -n '/^---$/,/^---$/p' "$f" | grep -oE '"[^"]+"' | tr -d '"' | while read -r pat; do
    printf '%5d  %s  %s\n' "$(git ls-files "$pat" | wc -l)" "$f" "$pat"
  done
done
```
그다음 새 세션에서 그 모듈 파일 하나를 열어 노트가 붙는지 본다.

### 5) 기록일 이후 바뀐 위치 찾기 (의심 항목 고르기)
```bash
# 노트 항목 끝의 (YYYY-MM-DD) 와 위치(클래스명)로, 그 뒤에 바뀐 파일인지 확인
since=2026-10-20
git log --since="$since" --format= --name-only -- '*BillingService*' | sort -u
```

### 6) 지침 파일별 글자 수 재기
```bash
# 매 세션 로드되는 파일과 스킬 본문의 글자 수(대략적인 컨텍스트 비용)
for f in CLAUDE.md AGENTS.md .claude/rules/*.md .claude/skills/*/SKILL.md; do
  [ -f "$f" ] && printf '%7d  %s\n' "$(wc -m < "$f")" "$f"
done | sort -rn
```

### 7) 스킬에서 조건부 절 떼어 내기
```markdown
<!-- .claude/skills/verify/SKILL.md -->
## 0. 서버로 실행해서 확인할 때
서버를 띄우거나 화면·API를 실행해서 확인하기 전에 같은 폴더의 `server.md`를 읽는다.
(컴파일·정적 검사만 하는 검증은 읽지 않는다)
```

### 8) 노트가 커밋 대상인지 확인
```bash
git check-ignore -v .claude/rules/ai/billing.md   # 출력이 있으면 ignore 규칙에 걸린 것
git ls-files .claude/rules                         # 추적 중인 노트
```

## 주의할 점
- `.gitignore`에 `.claude/**/*.md` 같은 규칙이 있으면 노트가 커밋되지 않아 팀과 공유되지 않는다. 의도한 것인지 확인한다.
- 존재하지 않는 경로 패턴은 오류 없이 그냥 아무것도 로드하지 않는다. 패턴마다 걸리는 파일 수를 확인한다.
- 지침 파일끼리 모순되면 모델이 아무 쪽이나 고를 수 있다. 주기적으로 모순과 낡은 참조를 점검한다.
