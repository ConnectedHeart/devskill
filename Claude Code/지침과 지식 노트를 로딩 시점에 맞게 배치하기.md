# 지침과 지식 노트를 로딩 시점에 맞게 배치하기

> 분류: Claude Code · 최근 갱신: 2026-10-21

## 한 줄 요약
Claude Code는 기능마다 컨텍스트에 올라가는 시점이 다르다. 모듈별 지식 노트는 `.claude/rules/` 아래에 `paths:`를 지정해 두면 그 경로 파일을 열 때만 자동으로 로드되므로, "작업 전에 노트를 다 읽어라" 같은 지시보다 싸고 확실하다.

## 내용
### 기능별 로딩 시점
| 위치 | 언제 로드되나 | 알맞은 용도 |
|---|---|---|
| CLAUDE.md (+ `@import`) | 매 세션 시작, 전체 | 매번 지킬 규칙. 200줄 이하 권장. import로 나눠도 비용은 같다 |
| `.claude/rules/*.md` (`paths` 없음) | 매 세션 시작 | CLAUDE.md를 주제별로 나눈 것 |
| `.claude/rules/*.md` (`paths:` 지정) | 그 경로의 파일을 Read/Write/Edit할 때만 | 특정 디렉터리·모듈에만 해당하는 지식 |
| 자동 메모리(MEMORY.md) | 매 세션, 앞부분만 | 코드로 알 수 없는 것만. 지침 파일에 이미 있는 내용은 넣지 않는다 |
| Skill | 설명만 항상, 본문은 쓸 때 | 절차, 양식, 체크리스트 |
| Hook·권한 설정 | 이벤트 때 외부에서 실행 | 반드시 지켜야 하는 규칙(지침 문구는 보장이 아니라 요청이다) |
| 서브에이전트 | 띄울 때, 별도 컨텍스트 | 많이 읽고 결론만 받아야 할 때 |

### 경로 지정 노트
- 파일 맨 위 frontmatter에 `paths:`로 글롭 패턴을 적는다. 그 패턴에 맞는 파일을 열거나 고치면 노트가 함께 붙는다. 관련 없는 작업에서는 컨텍스트를 쓰지 않는다.
- 하위 폴더(`.claude/rules/<이름>/`)로 묶어도 된다. 사람이 정한 규칙과 AI가 관리하는 노트를 폴더로 구분하기 좋다.
- 같은 세션에서 같은 노트는 처음 한 번만 붙는다. 경로가 겹치게 잡으면 한 파일이 노트 여러 개를 함께 부른다.
- rules 폴더는 세션 시작 때 찾는다. 노트를 새로 만든 그 세션에서는 자동 로드가 안 될 수 있으니 확인은 새 세션에서 한다.
- 다른 저장소에서 연 세션에서는 이 저장소의 rules가 자동으로 붙지 않는다. 다른 에이전트 도구(Codex 등)도 이 폴더를 자동으로 읽지 않는다.

### 무엇을 남기나
- **남긴다**: 사람의 결정과 이유, 외부 시스템 동작, 함정(코드만 보면 오해하는 것), 환경·테스트 특이점.
- **남기지 않는다**: 코드 구조 설명(코드를 직접 읽는 게 더 정확), 수정 경위(git log에 있음), 다른 문서에 이미 있는 규칙.
- 틀린 노트는 노트가 없는 것보다 나쁘다. 없으면 코드를 보지만, 있으면 믿고 따른다.
- 새 사실이 옛 줄과 부딪히면 덧붙이지 말고 옛 줄을 고치거나 지운다. 쓰기 전에 같은 키워드를 검색한다.
- 위치는 줄 번호 대신 `클래스.메소드`처럼 적는다. 줄 번호는 코드가 바뀌면 바로 틀어진다.
- 노트에 위치 표시가 있으면 "기록일 이후 그 파일이 바뀐 항목"을 스크립트로 골라 의심 항목으로 볼 수 있다.

## 예시
```markdown
---
paths:
  - "src/main/java/com/example/billing/**"
  - "src/main/webapp/js/billing/**"
---
# billing — 코드로 알 수 없는 것
- [결정] 환불 재시도는 1회만, 2회째는 수동 처리 (2026-10-20, 담당자 결정)
- [함정] 외부 PG 응답의 금액은 문자열로 온다. BillingService.parse에서 변환
```

로드 확인: 노트마다 패턴에 걸리는 파일이 실제로 있는지 `git ls-files '<패턴>'`으로 세어 보고, 새 세션에서 그 모듈 파일 하나를 열어 노트가 붙는지 본다.

## 주의할 점
- `.gitignore`에 `.claude/**/*.md` 같은 규칙이 있으면 노트가 커밋되지 않아 팀과 공유되지 않는다. 의도한 것인지 확인한다.
- 존재하지 않는 경로 패턴은 오류 없이 그냥 아무것도 로드하지 않는다. 패턴마다 걸리는 파일 수를 확인한다.
- 지침 파일끼리 모순되면 모델이 아무 쪽이나 고를 수 있다. 주기적으로 모순과 낡은 참조를 점검한다.
