# 예약 작업 무인 실행과 권한 규칙

> 분류: Claude Code · 최근 갱신: 2026-10-27

## 한 줄 요약
사람이 없는 시간에 도는 예약 작업은 허용 창이 뜨면 그대로 멈추므로, 작업이 쓰는 명령을 고정 스크립트로 만들고 그 명령과 폴더만 허용 규칙에 넣는다.

## 내용
### "항상 허용"을 눌러도 다음 날 또 멈추는 이유
- 허용은 **명령 문자열 단위**로 기억된다. 작업이 매번 즉석에서 명령이나 스크립트를 새로 만들면 문자열이 달라져 이전 허용이 맞지 않는다.
- 작업 폴더 밖의 파일(다른 폴더의 문서, 바탕화면 등)을 읽고 쓰는 것도 별도 허용이 필요하다.
- 사람이 있는 세션에서도 같다. 시험 스크립트의 파일명이나 앞에 붙는 환경 변수를 바꿔 가며 실행하면 매번 새 명령으로 보여 승인 창이 반복된다. 스크립트 파일명을 고정하고 내용만 바꾸면 한 번 허용한 명령이 계속 통한다.

### 해결: 고정 스크립트 + 좁은 허용 규칙
1. 작업이 해야 하는 셸 동작을 스크립트 파일로 고정한다(예: 추출 스크립트, 업로드 스크립트).
2. 설정의 `permissions.allow`에 그 스크립트 실행 명령과, 읽고 쓸 폴더만 넣는다.
3. 작업 지시문에 "이 명령만 정확히 실행하고 다른 셸 명령은 쓰지 말 것"을 명시한다.

- 규칙의 명령 문자열은 작업이 실제로 실행하는 문자열과 글자 단위로 같아야 한다(경로 구분자, 옵션 순서 포함).
- 인자가 달라지는 명령만 끝에 ` *`를 붙이고, 인자가 없는 명령은 정확히 일치하는 규칙으로 둔다.
- 스크립트가 마지막 줄에 `OK ...` / `FAIL ...` 같은 정해진 형식의 결과를 출력하게 하면 작업이 그 줄만 보고 다음 행동을 정할 수 있다.

### 실행 조건
- 예약 작업은 앱이 켜져 있을 때 실행된다. 앱이 꺼져 있었다면 다음에 켤 때 실행된다.
- 인터넷이 되는 상태여야 하고 PC가 절전이면 실행되지 않는다.
- 반복 작업은 지정 시각보다 몇 분 늦게 시작될 수 있다.
- 매 실행은 이전 대화를 기억하지 못하는 새 세션이다. 지시문만 보고 끝까지 할 수 있게 써야 한다.

### 못 돌았을 때의 보충
- 세션 시작 훅에서 "어제 결과물이 있는가"를 확인하고, 없으면 그날 첫 세션에서 사용자에게 물어 처리하게 한다.
- 거절했을 때는 표시 파일을 남겨 같은 것을 다시 묻지 않게 한다.

### 보충 장치에 생기기 쉬운 구멍
- **질문이 무인 실행에 소모된다**: "하루 첫 세션에서만 확인"하는 훅은 예약 실행 세션이 그날의 첫 세션이 되면 그쪽에서 발동한다. 무인 세션은 답할 사람이 없으므로 질문만 남고, 이후 사용자가 연 세션에는 안내가 뜨지 않는다. 훅에서 무인 세션을 구분하거나, "확인 완료" 표시는 사용자가 실제로 답한 뒤에만 남기도록 한다.
- **밀린 실행이 놓친 날을 처리하지 않는다**: 대상 날짜를 "실행 시점 기준 오늘(또는 어제)"로 계산하면, PC가 꺼져 있다가 뒤늦게 돈 실행은 놓친 날이 아니라 실행한 날을 대상으로 잡는다. 대상은 "결과물이 없는 날짜 목록"으로 구하는 편이 안전하다.
- **가장 최근 하루만 확인한다**: 직전 하루만 보면 그보다 앞선 날짜가 여러 개 빠져 있어도 잡아내지 못한다. 일정 기간(예: 최근 14일)을 훑어 빠진 날짜를 모두 찾는다.
- **무인 세션 구분은 UserPromptSubmit 훅에서**: SessionStart 훅은 세션이 무엇으로 시작됐는지 알 수 없다. 프롬프트 내용을 받는 UserPromptSubmit 훅으로 옮기고, 예약 작업 프롬프트(예약 작업 표식으로 시작하는 프롬프트)이면 아무것도 하지 않고 "확인 완료" 표시도 남기지 않게 하면 질문이 사람이 연 첫 세션까지 살아남는다.
- **작업한 날은 사람 메시지 시각으로 센다**: 대화 기록 파일의 수정 시각으로 세면 예약 작업 세션에서 이어 대화한 날이나 자정을 넘긴 세션이 엉뚱한 날로 잡힌다.
- **성공 상태가 결과물을 보장하지 않는다**: 실행 이력이 "성공"이어도 몇 초 만에 끝난 실행은 실제로는 아무것도 만들지 않았을 수 있다. 상태가 아니라 결과물(파일·폴더)이 있는지로 확인한다.

### 권한 요청에서 멈춘 실행이 뒤 실행까지 막는 경우
- 무인 실행 중 허용 규칙에 맞지 않는 명령이 나오면 권한 요청이 뜬다. 이 요청은 응답할 사람이 없어 에러(`Tool permission stream closed before response received`)로 끝날 때도 있지만, 닫히지 않고 **무기한 대기**할 때도 있다.
- 대기에 걸린 실행은 며칠이고 "실행 중"으로 남는다. 관찰한 사례에서는 그동안 다음 날짜의 예약 실행이 시작되지 않았다(앞 실행이 끝나지 않아서라는 것은 추정).
- 구분 방법: 실행 세션의 프로세스는 살아 있는데 호출한 명령의 자식 프로세스도, 명령이 남겼어야 할 결과(커밋·파일)도 없으면 명령 실행 전 승인 단계에서 멈춘 것이다. 폴더 쓰기 권한 문제와는 다르다.
- 같은 명령이라도 허용 규칙이 사용자 설정에만 있는 것은 예약 실행에서 권한 요청이 떴고, 프로젝트 설정에도 있는 것은 통과했다. 원인은 확인하지 못했으므로, 무인 실행에 필요한 규칙은 실제 무인 실행에서 통과하는지 직접 확인한다.
- 가장 확실한 대응은 **외부로 내보내는 동작(업로드·push)을 무인 실행에서 빼는 것**이다. 무인 실행은 결과물을 로컬에 만들기만 하고, 다음 날 사람이 있는 첫 세션에서 "올릴까요?"를 물은 뒤 실행한다.
- 멈춘 실행은 그 세션을 열어 승인하거나 중지하면 풀린다.

### 긴 대화 기록을 싸게 요약하기
- 대화 전체를 읽히면 대부분이 중간 진행 메시지와 버릴 주제다.
- 추출 스크립트가 **목차**(질문 앞부분 + 최종 답변의 줄 범위)를 따로 만들고, 작업은 목차만 읽어 주제를 분류한 뒤 필요한 주제의 최종 답변 줄만 읽는다.
- 실측에서 목차는 전체의 약 4% 크기였다. 중간 메시지만 빼는 것으로는 약 26%밖에 줄지 않았고, 실제 절감은 쓰지 않을 주제의 답변을 건너뛰는 데서 나왔다.

## 핵심 코드
### 1) 고정 스크립트와 좁은 허용 규칙
```json
{
  "permissions": {
    "allow": [
      "PowerShell(powershell -NoProfile -ExecutionPolicy Bypass -File C:/Users/<사용자>/.claude/mytask/extract.ps1 *)",
      "PowerShell(powershell -NoProfile -ExecutionPolicy Bypass -File C:/Users/<사용자>/.claude/mytask/upload.ps1)",
      "Read(~/.claude/mytask/**)",
      "Read(~/Desktop/<출력 폴더>/**)",
      "Edit(~/Desktop/<출력 폴더>/**)"
    ]
  }
}
```
무인 실행에 필요한 규칙은 사용자 설정뿐 아니라 프로젝트 설정(`.claude/settings.json`)에도 넣고, 실제 무인 실행에서 통과하는지 확인한다.

### 2) 마지막 줄을 OK/FAIL로 끝내는 스크립트 (extract.ps1)
```powershell
param([Parameter(Mandatory)][string]$Date)            # 예: 2026-01-31
$ErrorActionPreference = 'Stop'
try {
    $out = Join-Path $HOME "Desktop\<출력 폴더>\$Date"
    New-Item -ItemType Directory -Force -Path $out | Out-Null
    # ... 추출 작업 ...
    "OK $out"
    exit 0
} catch {
    "FAIL $($_.Exception.Message)"
    exit 1
}
```

### 3) 작업 지시문 (예약 작업 프롬프트)
```text
[scheduled-task] 매일 정리 작업
1. 아래 명령만 정확히 실행한다. 다른 셸 명령은 쓰지 않는다.
   powershell -NoProfile -ExecutionPolicy Bypass -File C:/Users/<사용자>/.claude/mytask/extract.ps1 <대상 날짜>
2. 대상 날짜는 최근 14일 중 ~/Desktop/<출력 폴더>/<날짜> 폴더가 없는 날짜 전부다.
3. 출력 마지막 줄이 FAIL 이면 그 날짜는 건너뛰고 끝에 목록으로 남긴다.
4. 업로드·push 는 하지 않는다.
```

### 4) 무인 세션을 건너뛰는 UserPromptSubmit 훅
```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command", "command": "bash ~/.claude/mytask/first-prompt.sh", "timeout": 10 } ] }
    ]
  }
}
```
```bash
#!/usr/bin/env bash
# ~/.claude/mytask/first-prompt.sh — 훅 입력 JSON 은 표준 입력으로 들어온다
out_dir="$HOME/Desktop/output"                             # 결과물 폴더로 바꾼다
input=$(cat)
echo "$input" | grep -qE '"prompt"[[:space:]]*:[[:space:]]*"\[scheduled-task\]' && exit 0   # 예약 작업이면 아무것도 안 함
[ -f ~/.claude/mytask/answered-$(date +%F) ] && exit 0      # 사용자가 이미 답한 날
missing=""
for i in $(seq 1 14); do                                    # 최근 14일 중 결과물이 없는 날짜
  d=$(date -d "-$i day" +%F)
  [ -d "$out_dir/$d" ] || missing="$missing $d"
done
[ -z "$missing" ] && exit 0                                 # 할 일 없으면 출력하지 않는다
echo "Missing outputs for:$missing. In your first reply, ask the user (in Korean) whether to process them now. After the user answers, create ~/.claude/mytask/answered-$(date +%F)."
```

### 5) 설정 파일이 JSON으로 읽히는지 확인
```powershell
Get-Content ~/.claude/settings.json -Raw | ConvertFrom-Json | Out-Null; if ($?) { 'OK' }
Get-Content .claude/settings.json -Raw | ConvertFrom-Json | Select-Object -ExpandProperty permissions
```

## 주의할 점
- 설정 파일은 JSON이라 쉼표 하나만 빠져도 전체가 읽히지 않는다. 고친 뒤 파싱되는지 확인한다.
- 외부로 내보내는 동작(업로드, push)을 무인으로 돌릴 때는 스크립트 안에 안전 확인을 넣는다: 대상 주소가 예상과 같은지, 공개 범위가 바뀌지 않았는지, 인증 창을 띄우고 멈추지 않는지.
- 무인 실행이 실패해도 다음 실행에서 밀린 것까지 처리되게 만들면 하루 실패가 누락으로 이어지지 않는다.
- 허용 창이 실제로 떴는지는 작업 쪽에서 알 수 없다. 처음 며칠은 실행 결과를 직접 확인한다.
