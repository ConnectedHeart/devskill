# 예약 작업 무인 실행과 권한 규칙

> 분류: Claude Code · 최근 갱신: 2026-10-05

## 한 줄 요약
사람이 없는 시간에 도는 예약 작업은 허용 창이 뜨면 그대로 멈추므로, 작업이 쓰는 명령을 고정 스크립트로 만들고 그 명령과 폴더만 허용 규칙에 넣는다.

## 내용
### "항상 허용"을 눌러도 다음 날 또 멈추는 이유
- 허용은 **명령 문자열 단위**로 기억된다. 작업이 매번 즉석에서 명령이나 스크립트를 새로 만들면 문자열이 달라져 이전 허용이 맞지 않는다.
- 작업 폴더 밖의 파일(다른 폴더의 문서, 바탕화면 등)을 읽고 쓰는 것도 별도 허용이 필요하다.

### 해결: 고정 스크립트 + 좁은 허용 규칙
1. 작업이 해야 하는 셸 동작을 스크립트 파일로 고정한다(예: 추출 스크립트, 업로드 스크립트).
2. 설정의 `permissions.allow`에 그 스크립트 실행 명령과, 읽고 쓸 폴더만 넣는다.
3. 작업 지시문에 "이 명령만 정확히 실행하고 다른 셸 명령은 쓰지 말 것"을 명시한다.

- 규칙의 명령 문자열은 작업이 실제로 실행하는 문자열과 글자 단위로 같아야 한다(경로 구분자, 옵션 순서 포함).
- 인자가 달라지는 명령만 끝에 ` *`를 붙이고, 인자가 없는 명령은 정확히 일치하는 규칙으로 둔다.
- 스크립트가 마지막 줄에 `OK ...` / `FAIL ...` 같은 정해진 형식의 결과를 출력하게 하면 작업이 그 줄만 보고 다음 행동을 정할 수 있다.

### 실행 조건
- 예약 작업은 앱이 켜져 있을 때 실행된다. 앱이 꺼져 있었다면 다음에 켤 때 실행된다.
- 인터넷이 되는 상태여야 하고 PC가 절전이면 실행되지 않는다.
- 반복 작업은 지정 시각보다 몇 분 늦게 시작될 수 있다.
- 매 실행은 이전 대화를 기억하지 못하는 새 세션이다. 지시문만 보고 끝까지 할 수 있게 써야 한다.

### 못 돌았을 때의 보충
- 세션 시작 훅에서 "어제 결과물이 있는가"를 확인하고, 없으면 그날 첫 세션에서 사용자에게 물어 처리하게 한다.
- 거절했을 때는 표시 파일을 남겨 같은 것을 다시 묻지 않게 한다.

### 보충 장치에 생기기 쉬운 구멍
- **질문이 무인 실행에 소모된다**: "하루 첫 세션에서만 확인"하는 훅은 예약 실행 세션이 그날의 첫 세션이 되면 그쪽에서 발동한다. 무인 세션은 답할 사람이 없으므로 질문만 남고, 이후 사용자가 연 세션에는 안내가 뜨지 않는다. 훅에서 무인 세션을 구분하거나, "확인 완료" 표시는 사용자가 실제로 답한 뒤에만 남기도록 한다.
- **밀린 실행이 놓친 날을 처리하지 않는다**: 대상 날짜를 "실행 시점 기준 오늘(또는 어제)"로 계산하면, PC가 꺼져 있다가 뒤늦게 돈 실행은 놓친 날이 아니라 실행한 날을 대상으로 잡는다. 대상은 "결과물이 없는 날짜 목록"으로 구하는 편이 안전하다.
- **가장 최근 하루만 확인한다**: 직전 하루만 보면 그보다 앞선 날짜가 여러 개 빠져 있어도 잡아내지 못한다. 일정 기간(예: 최근 14일)을 훑어 빠진 날짜를 모두 찾는다.
- **성공 상태가 결과물을 보장하지 않는다**: 실행 이력이 "성공"이어도 몇 초 만에 끝난 실행은 실제로는 아무것도 만들지 않았을 수 있다. 상태가 아니라 결과물(파일·폴더)이 있는지로 확인한다.

### 긴 대화 기록을 싸게 요약하기
- 대화 전체를 읽히면 대부분이 중간 진행 메시지와 버릴 주제다.
- 추출 스크립트가 **목차**(질문 앞부분 + 최종 답변의 줄 범위)를 따로 만들고, 작업은 목차만 읽어 주제를 분류한 뒤 필요한 주제의 최종 답변 줄만 읽는다.
- 실측에서 목차는 전체의 약 4% 크기였다. 중간 메시지만 빼는 것으로는 약 26%밖에 줄지 않았고, 실제 절감은 쓰지 않을 주제의 답변을 건너뛰는 데서 나왔다.

## 예시
```json
{
  "permissions": {
    "allow": [
      "PowerShell(powershell -NoProfile -ExecutionPolicy Bypass -File C:/Users/<사용자>/.claude/mytask/extract.ps1 *)",
      "PowerShell(powershell -NoProfile -ExecutionPolicy Bypass -File C:/Users/<사용자>/.claude/mytask/upload.ps1)",
      "Read(~/.claude/mytask/**)",
      "Read(~/Desktop/<출력 폴더>/**)",
      "Edit(~/Desktop/<출력 폴더>/**)"
    ]
  }
}
```

## 주의할 점
- 설정 파일은 JSON이라 쉼표 하나만 빠져도 전체가 읽히지 않는다. 고친 뒤 파싱되는지 확인한다.
- 외부로 내보내는 동작(업로드, push)을 무인으로 돌릴 때는 스크립트 안에 안전 확인을 넣는다: 대상 주소가 예상과 같은지, 공개 범위가 바뀌지 않았는지, 인증 창을 띄우고 멈추지 않는지.
- 무인 실행이 실패해도 다음 실행에서 밀린 것까지 처리되게 만들면 하루 실패가 누락으로 이어지지 않는다.
- 허용 창이 실제로 떴는지는 작업 쪽에서 알 수 없다. 처음 며칠은 실행 결과를 직접 확인한다.
