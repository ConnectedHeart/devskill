# MCP 서버 도입 판단과 Serena(jdtls)

> 분류: Claude Code · 최근 갱신: 2026-10-21

## 한 줄 요약
MCP 서버는 정해진 도구와 비밀값 격리가 장점이지만, 망이 분리된 자원에는 맞지 않을 수 있다. Java 영향 범위 분석에는 jdtls 기반 Serena가 grep보다 정확하지만, 문자열로 연결된 JSP·JS·XML 참조는 여전히 grep이 필요하다.

## 내용
### MCP로 붙일 때의 장점
- `query`, `list_tables`, `describe` 같은 정해진 도구라 SQL 파일을 쓰고 결과를 다시 읽는 과정이 없다.
- 결과를 표 형태로 받아 셸 인용 문제나 인코딩 깨짐이 줄어든다.
- 접속 정보는 MCP 서버 설정 안에만 있고 에이전트에게는 보이지 않는다.
- 도구마다 권한을 `ask`로 걸 수 있다.

### 맞지 않는 경우: 망 분리
- 에이전트의 API 통신은 외부망에서만 되고 대상 자원은 내부망에서만 닿는 환경이면, 상주 프로세스인 MCP 서버의 연결은 망이 바뀔 때마다 끊긴다.
- 호출마다 망을 바꾸게 만들면 기존의 "망 전환 → 실행 → 복귀" 래퍼와 같은 일을 하면서, 승인된 래퍼 밖에서 망 전환이 일어나게 된다. 이 경우 기존 래퍼 + 읽기 전용 실행 도구를 유지하는 편이 낫다.

### 맞는 경우: 같은 PC의 로컬 DB
- 접속 정보를 에이전트가 볼 수 없는 파일에 두고 있다면, 읽기 전용 MCP로 붙여 에이전트가 직접 조회할 수 있게 하는 효과가 크다.
- 조건: DB 계정 자체를 SELECT 권한만 있게 만든다(MCP 서버의 "읽기 전용" 옵션만 믿지 않는다. 커뮤니티 MySQL MCP 중에는 설정하지 않으면 쓰기를 허용하는 것도 있다). 접속 정보는 사람이 직접 넣는다. 외부 패키지라 출처와 버전을 확인한다.

### REST API를 쓰는 서비스
- 이슈 트래커처럼 API 키로 REST를 직접 부르고 있다면 꼭 MCP로 바꿀 필요는 없다. API 키는 키 주인 계정과 같은 권한이므로 잘못된 PUT은 실제 데이터를 바꾼다. MCP로 바꾸면 인코딩·페이지 넘기기 실수가 줄지만, 키를 든 프로세스가 상주한다.

### Serena와 jdtls
- **jdtls**(Eclipse JDT Language Server): Eclipse의 Java 분석 엔진을 LSP로 떼어 낸 것. VS Code Java 확장의 "정의로 이동", "참조 찾기", "호출 계층"이 이 엔진이다. `pom.xml`로 클래스패스를 잡아 오버로드, 같은 이름의 다른 메소드, 인터페이스와 구현체를 구분한다.
- **Serena**: 오픈소스(MIT) MCP 서버. 언어마다 언어 서버를 붙여 쓰고 Java에는 jdtls를 쓴다. `find_symbol`, `find_referencing_symbols`, `get_symbols_overview`, 심볼 본문 교체 같은 심볼 단위 도구를 준다.

| 질문 | grep | Serena(jdtls) |
|---|---|---|
| 이 메소드를 누가 부르나 | 같은 이름의 다른 클래스 메소드까지 섞임 | 그 메소드 호출부만 |
| 인터페이스 메소드를 바꾸면 영향은 | 구현체·호출부를 직접 따라감 | 바로 찾음 |
| JSP/JS에서 URL 문자열로 부르는 곳 | 찾음 | 못 찾음 |
| XML 매퍼의 SQL ID 참조 | 찾음 | 못 찾음 |

### 효과가 적은 경우
- 라이브러리 문서 MCP(Context7 등)는 오래된 프레임워크·버전을 거의 다루지 않아 효과가 적다.
- 로컬 로그 파일은 파일 읽기 도구로 충분하다.

## 예시
```
설치 전 확인 목록 (Serena)
- Python 기반, 보통 uv로 실행 → PC에 Python이 없으면 uv가 받아 쓰는지 확인
- jdtls는 JDK 17 이상으로 실행 (대상 프로젝트가 Java 8이어도 무관)
- Maven 의존성이 사내 저장소에서만 받아지는 것이면 ~/.m2에 이미 있어야 분석이 정확
- 큰 프로젝트는 첫 색인에 시간이 걸림
```

## 주의할 점
- 쓰기 기능이 있는 MCP 도구는 권한을 `ask`로 둔다.
- MCP를 써도 "SQL 전문을 보여 주고 승인받은 뒤 실행" 같은 기존 규칙은 그대로 지킨다.
