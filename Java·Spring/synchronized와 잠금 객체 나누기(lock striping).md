# synchronized와 잠금 객체 나누기(lock striping)

> 분류: Java·Spring · 최근 갱신: 2026-10-07

## 한 줄 요약
`synchronized`는 같은 잠금 객체에 대해 한 번에 한 스레드만 블록에 들어가게 하는 장치이고, 키별로 줄을 세우고 싶을 때는 미리 만든 잠금 객체 N개 중 하나를 키의 해시로 고르는 방식(lock striping)을 쓴다.

## 내용
- **왜 필요한가**: 웹 서버는 요청마다 스레드를 배정하므로 같은 코드가 동시에 실행된다. "읽고 → 판단하고 → 바꾸는" 작업이 겹치면 두 요청이 같은 옛 값을 보고 각자 처리해 결과가 꼬인다(재고 1개가 두 번 팔리는 식).
- **동작**: 자바의 모든 객체는 잠금 표시(모니터)를 하나씩 가진다. `synchronized (obj) { ... }`는 들어갈 때 그 객체의 잠금을 잡고, 이미 잡혀 있으면 기다리며, 나갈 때(예외로 나가도) 푼다. 객체의 타입이나 값은 상관없고 "같은 객체인가"만 본다.
- **기다린 쪽은 블록 안에서 다시 읽어야 한다**: 잠금 밖에서 읽은 값으로 판단하면 줄을 세운 의미가 없다. 앞 스레드가 저장한 결과를 블록 안에서 다시 읽고, 이미 처리돼 있으면 그대로 쓴다.
- **키별 잠금을 만드는 세 가지 선택**
  - 잠금 하나로 전체를 막기: 서로 무관한 사용자까지 한 줄로 선다.
  - 키마다 잠금 객체 만들기: 키 수만큼 객체가 쌓여 따로 정리해야 한다.
  - 고정 개수(예: 64개)로 나누기: 같은 키는 항상 같은 잠금을 고르고, 다른 키끼리는 대부분 겹치지 않는다. 버킷이 N개인 해시 테이블과 번호를 고르는 방식은 같지만, 칸에 데이터를 넣지 않고 충돌도 처리하지 않는다. 충돌하면 서로 잠깐 기다릴 뿐 결과는 틀려지지 않는다.
- **문자열 키를 직접 잠금으로 쓰면 안 되는 이유**: 요청마다 새로 만들어진 문자열은 내용이 같아도 서로 다른 객체라 아무도 기다리지 않는다.
- **성능**: 경합이 없을 때 `synchronized` 자체는 수십 나노초 수준이다. 비용은 잠금이 아니라 블록 안에서 하는 일(외부 호출 등)에서 나온다. 그래서 대부분의 요청이 잠금 없이 끝나도록 빠른 경로를 앞에 두고, 꼭 필요한 구간만 감싼다.
- **한계**: 한 JVM 안에서만 통한다. 서버가 여러 대면 DB 행 잠금 같은 공유 잠금이 따로 필요하다. 이때도 `synchronized`를 함께 두면, 같은 서버의 대기 요청이 DB 커넥션을 잡지 않고 메모리에서 줄을 서게 되어 커넥션을 아낀다.

## 예시
```java
private static final Object[] LOCKS = new Object[64];
static {
    for (int i = 0; i < LOCKS.length; i++) {
        LOCKS[i] = new Object();
    }
}

Object lockFor(String key) {
    // & 0x7fffffff: hashCode()가 음수일 때 인덱스가 음수가 되지 않게 부호 비트를 지운다
    return LOCKS[(key.hashCode() & 0x7fffffff) % LOCKS.length];
}

String resolve(String key) {
    Value v = load(key);
    if (v.isUsable()) {
        return v.get();              // 빠른 경로: 잠금 없음
    }
    synchronized (lockFor(key)) {
        v = load(key);               // 잠금 안에서 다시 읽는다
        if (!v.isUsable()) {
            v = refreshAndSave(key);
        }
        return v.get();
    }
}
```

## 주의할 점
- 잠금을 쥔 채 느린 외부 호출을 하면 같은 잠금에 걸린 요청이 그 타임아웃만큼 기다린다. 외부 시스템 장애 시 요청 스레드가 쌓일 수 있으므로 "실패 후 일정 시간 재시도하지 않기"를 따로 고려한다.
- 다른 키끼리 겹치는 것이 신경 쓰이면 잠금 개수만 늘리면 된다(64 → 256, 1024).
- `synchronized`를 트랜잭션이 걸린 메서드 안쪽에 두면 커넥션을 먼저 잡고 줄을 서게 된다. 잠금은 트랜잭션을 여는 호출의 바깥에서 잡는다.
