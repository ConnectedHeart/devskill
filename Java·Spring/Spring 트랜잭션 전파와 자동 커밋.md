# Spring 트랜잭션 전파와 자동 커밋

> 분류: Java·Spring · 최근 갱신: 2026-10-07

## 한 줄 요약
트랜잭션 매니저는 쿼리를 실행하는 장치가 아니라 자동 커밋을 끄고 여러 쿼리를 한 커넥션으로 묶는 장치이며, 외부 시스템을 바꾸는 작업은 호출한 쪽 트랜잭션과 분리(REQUIRES_NEW)해야 롤백으로 어긋나지 않는다.

## 내용
- **트랜잭션이 없어도 쿼리는 동작한다**: JDBC 커넥션은 기본이 자동 커밋이라 쿼리 하나가 끝나면 바로 확정된다. DAO가 풀에서 커넥션을 빌려 쓰고 바로 반납한다.
- **부품별 역할**
  - 커넥션 풀(DataSource): 커넥션을 미리 만들어 보관하고 빌려준다. 트랜잭션 유무와 무관하게 항상 동작한다.
  - DAO/매퍼: 쿼리 전에 빌리고 끝나면 반납한다.
  - 트랜잭션 매니저: 트랜잭션 동안 커넥션 하나를 스레드에 붙잡아 두고, 끝날 때 커밋·롤백 후 반납한다.
- **트랜잭션이 필요한 경우는 둘**: 여러 쿼리가 전부 성공하거나 전부 취소되어야 할 때, 그리고 행 잠금을 여러 쿼리에 걸쳐 유지해야 할 때(`SELECT ... FOR UPDATE`의 잠금은 자동 커밋이면 그 쿼리 직후 풀린다).
- **트랜잭션은 스레드에 묶인다**: 트랜잭션 설정이 없는 클래스의 메서드라도, 호출 시점에 그 스레드에 트랜잭션이 열려 있으면 그 안의 쿼리는 같은 커넥션으로 그 트랜잭션에 포함된다.
- **선언적(AOP) 트랜잭션의 함정**
  - 이름 패턴 포인트컷(`*Impl` 등)으로 일괄 적용하는 프로젝트에서는 패턴에 맞지 않는 클래스에 트랜잭션이 아예 걸리지 않는다.
  - 프록시를 거치지 않는 같은 클래스 내부 호출(private 메서드 포함)에는 적용되지 않는다. 메서드 하나만 다른 규칙으로 돌리려면 별도 빈으로 빼야 한다.
  - 설정이 안 맞아도 오류 없이 트랜잭션만 빠진 채 돈다. `TransactionSynchronizationManager.isActualTransactionActive()`를 로그로 찍어 확인한다.
- **전파 방식**
  - REQUIRED(기본): 호출한 쪽 트랜잭션이 있으면 합류, 없으면 새로 시작.
  - REQUIRES_NEW: 항상 새로 시작하고 끝나면 바로 커밋. 바깥 트랜잭션과 별개의 커넥션을 쓴다.
- **외부 시스템을 바꾸는 작업은 REQUIRES_NEW가 맞다**: 외부 API 호출 결과(예: 인증 서버가 옛 refresh token을 폐기하고 새것 발급)는 DB 롤백으로 되돌릴 수 없다. 바깥 트랜잭션에 합류했다가 뒤에서 예외가 나 롤백되면, DB에는 이미 폐기된 옛 값이 남는다. 또 행 잠금이 바깥 트랜잭션이 끝날 때까지 유지되어 다른 서버가 불필요하게 오래 기다린다.
- **"예외를 던지면서 커밋도 해야 하는" 상황은 구조로 없앤다**: 기본 규칙은 예외 시 롤백이다. 실패 시 정리(죽은 행 삭제 등)를 트랜잭션 안에서 하고 예외를 던지면 삭제까지 취소된다. `no-rollback-for` 같은 특수 규칙을 늘리기보다, 트랜잭션 안에서는 실패 시 평범하게 롤백하고 정리 작업을 트랜잭션이 끝난 뒤(바깥 catch)에서 한다. 이미 죽은 데이터를 지우는 것이라 잠금 밖에서 해도 결과가 같고, 중복 삭제는 영향이 없다.

## 예시
```java
// 별도 빈: 새 트랜잭션에서 "잠그고 실행"만 담당
@Service
public class RowLockService {
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public <T> T withLockedRow(String key, Function<Row, T> work) {
        Row row = dao.selectForUpdate(key);   // 이 트랜잭션이 끝날 때까지 행 잠금 유지
        return work.apply(row);
    }
}

// 호출하는 쪽: 트랜잭션 없음
try {
    return rowLockService.withLockedRow(key, row -> refreshAndSave(row));
} catch (GrantExpiredException e) {
    dao.delete(key);   // 트랜잭션이 롤백으로 끝난 뒤, 자동 커밋으로 단독 실행
    throw e;
}
```

## 주의할 점
- REQUIRES_NEW는 바깥 트랜잭션이 있으면 요청 하나가 커넥션 두 개를 쓴다. 풀 크기가 작으면 고갈·교착에 주의한다.
- 트랜잭션 안에서 느린 외부 호출을 하면 그 시간 내내 커넥션과 잠금을 잡는다. 외부 호출에는 짧은 타임아웃을 둔다.
- 클래스 전체에 트랜잭션을 걸면, HTTP 호출이 대부분인 서비스는 대기 시간 내내 커넥션을 묶는다. 묶어야 하는 구간만 트랜잭션으로 만든다.
- 트랜잭션이 걸린 서비스 안에서 호출되고 예외가 밖으로 나가면, 트랜잭션 밖이라고 생각한 삭제도 그 바깥 트랜잭션과 함께 롤백될 수 있다.
- MySQL 기본 격리 수준에서 일반 SELECT는 트랜잭션 시작 시점 스냅샷을 읽지만, `SELECT ... FOR UPDATE`는 최신 커밋된 행을 읽는다.
