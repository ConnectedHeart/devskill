# 시작프로그램을 꺼도 다시 켜지는 앱 정리

> 분류: Windows·자동화 · 최근 갱신: 2026-11-06

## 한 줄 요약
작업 관리자에서 시작프로그램을 꺼도 다시 켜지는 앱은 앱 자체의 "로그인 시 열기" 설정이 실행될 때마다 등록을 되살리는 경우가 많고, 스토어(MSIX) 앱은 레지스트리가 아니라 패키지의 StartupTask로 등록된다.

## 내용
### 시작 등록이 들어가는 곳
| 종류 | 위치 | 끄는 법 |
|---|---|---|
| 일반 데스크톱 앱 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 값 | 값 삭제, 또는 작업 관리자에서 사용 안 함 |
| 사용 안 함 표시 | `HKCU\...\Explorer\StartupApproved\Run` | 작업 관리자의 사용/사용 안 함이 여기에 기록됨 |
| 시작 폴더 | `shell:startup` | 바로가기 삭제 |
| 스토어(MSIX) 앱 | 패키지 매니페스트의 StartupTask | 설정 > 앱 > 시작프로그램, 또는 StartupTask 끄기 |

### 다시 켜지는 이유
- Electron 계열 앱(노트 앱, 메신저 등)은 앱 설정에 "로그인 시 열기"가 있고, 켜져 있으면 앱이 실행될 때마다 Run 값을 다시 쓴다. 작업 관리자에서만 끄면 다음 실행 때 되살아날 수 있다.
- 그래서 **앱 설정을 먼저 끄고** 그다음 Run 값을 지운다. 앱이 실행 중이면 종료 시 설정 파일을 덮어쓰므로 앱을 끈 상태에서 설정 파일을 고쳐야 한다.
- `StartupApproved`에 이름만 남아 있어도 Run 값이 없으면 아무것도 실행되지 않는다.

### 스토어 앱
- 화면 이름과 패키지 이름이 다를 수 있다. `Get-AppxPackage`로 패키지를 찾는다.
- StartupTask를 사용자가 끈 상태(DisabledByUser)로 두면 앱이 스스로 다시 켤 수 없다. 설정 > 앱 > 시작프로그램의 스위치와 같은 상태다.

## 핵심 코드
### 1) 일반 앱 등록 확인·삭제
```powershell
# 등록된 시작 항목
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run'
# 앱 설정을 먼저 끈 뒤 등록 삭제 (이름은 위 결과에서 확인)
Remove-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -Name '<앱 등록 이름>'
```

### 2) 앱 설정 파일을 고치기 전 백업
```powershell
Stop-Process -Name '<앱 프로세스>' -ErrorAction SilentlyContinue   # 실행 중이면 종료 때 덮어씀
Copy-Item "$env:APPDATA\<앱>\<설정파일>.json" "$env:APPDATA\<앱>\<설정파일>.json.bak-$(Get-Date -f yyyyMMdd)"
```

### 3) 스토어 앱 패키지와 시작 작업 확인
```powershell
Get-AppxPackage | Where-Object Name -like '*<앱 이름 일부>*' | Select-Object Name, PackageFamilyName
Get-CimInstance Win32_StartupCommand | Select-Object Name, Command, Location   # 일반 시작 항목 전체 보기
```

## 주의할 점
- 고친 뒤에는 앱을 다시 실행해 Run 값이 다시 생기지 않는지 확인한다. 실제 효과는 재부팅해야 확정된다.
- 다시 켜려면 시작프로그램 스위치와 앱 설정을 둘 다 켜야 한다.
