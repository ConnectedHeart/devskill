# 실시간 변경 알림 대신 제출 시 버전 검사

> 분류: 네트워크 / 웹소켓 · 최근 갱신: 2026-11-02

## 한 줄 요약
"다른 사람이 내용을 바꾸면 열려 있는 화면에 알린다"를 웹소켓으로 만들기보다, 화면을 열 때 받은 수정 시각(버전)을 제출 때 함께 보내 서버가 비교하고 다르면 거부하는 편이 정확하고 이중화 환경에서도 안전하다.

## 내용
### 웹소켓 알림이 이 용도에 맞지 않는 이유
- **정확성을 보장하지 못한다.** 연결이 잠깐 끊기거나 메시지를 놓치면 바뀐 내용에 그대로 제출된다. 결국 제출 시 서버 검사가 있어야 하고, 그러면 알림은 "조금 빨리 알려 주는" 편의 기능일 뿐이다.
- **이중화 환경에서 빠진다.** 메시지 브로커가 WAS 메모리(Spring `enableSimpleBroker`)에 있으면 변경 요청을 받은 서버에 붙은 사용자에게만 간다. 모든 서버가 공유하려면 Redis·RabbitMQ 같은 외부 브로커가 필요하다.
- **실패했을 때 더 나쁘다.** 연결이 끊기면 새로고침하는 식으로 만들면, 프록시·방화벽이 웹소켓을 막는 환경에서는 계속 새로고침되어 작성 중 입력이 사라진다.
- **드문 사건에 비해 비용이 크다.** 화면을 연 사람 모두가 연결을 계속 유지한다.
- 웹소켓이 맞는 경우: 서버가 자주 먼저 보내야 하고 즉시성이 기능의 핵심일 때(채팅, 실시간 집계, 스트리밍). 이때도 외부 브로커와 "새로고침 대신 재연결"이 필요하다.

### 제출 시 버전 검사 (낙관적 잠금)
- 화면을 열 때 대상의 수정 시각(또는 버전 번호)을 받아 두고, 제출할 때 함께 보낸다.
- 서버는 저장 직전에 같은 쿼리로 현재 값을 다시 읽어 비교하고, 다르면 저장하지 않고 "내용이 바뀌었습니다" 코드로 거부한다. 화면은 안내 후 최신 내용으로 다시 연다(입력은 문항이 바뀌었을 수 있으므로 옮기지 않음).
- 검사 순서를 정해 둔다(예: 권한 → 기간 → 버전). 앞 검사에 걸리면 그 안내가 대신 나간다.
- 엄밀히 하려면 비교와 저장을 한 번에: `UPDATE ... WHERE id = ? AND version = ?`의 갱신 행 수가 0이면 거부.

### 함정
- **어떤 변경이 수정 시각을 바꾸는지 확인한다.** 다른 사람의 응답·조회수처럼 본문과 무관한 갱신이 수정 시각을 바꾸면, 아무도 수정하지 않았는데 거부된다. 반대로 본문을 바꾸는데 수정 시각을 안 바꾸는 경로가 있으면 검사가 뚫린다.
- **문자열로 비교할 때 형식·시간대를 맞춘다.** 화면에 준 값과 서버가 비교용으로 읽는 값이 같은 쿼리·같은 시간대 보정을 거쳐야 한다. 모바일과 웹이 사용자 시간대를 다른 곳에서 읽으면 수정하지 않은 대상도 모두 거부될 수 있다.
- **열어 둔 창의 부모 창(opener)이 없을 수 있다.** 오래 열어 둔 팝업일수록 목록 창이 닫혀 있을 가능성이 크다. `window.opener` 확인 없이 부모를 새로고침하면 예외로 멈춰 창이 닫히거나 다시 열리지 않는다.

## 핵심 코드
### 1) 클라이언트: 연 시점의 버전을 함께 제출
```javascript
var loadedVersion = survey.updatedAt;            // 화면을 열 때 받은 값
$.post('/api/surveys/' + id + '/answers', { answers: collect(), version: loadedVersion })
  .done(function (res) {
    if (res.code === 'MODIFIED') {
      alert('작성자가 내용을 수정했습니다. 다시 불러옵니다.');
      refreshOpenerSafely();
      location.reload();
    }
  });

function refreshOpenerSafely() {
  try {
    if (window.opener && !window.opener.closed) window.opener.location.reload();
  } catch (e) { /* 다른 출처 등 접근 불가 */ }
}
```

### 2) 서버: 저장 직전 비교
```java
public Result saveAnswers(long surveyId, String userId, List<Answer> answers, String clientVersion) {
    Survey current = surveyDao.findById(surveyId);           // 화면에 준 것과 같은 쿼리·형식
    if (!current.isInPeriod(now())) return Result.of("OUT_OF_PERIOD");
    if (clientVersion != null && !clientVersion.equals(current.getUpdatedAt())) {
        return Result.of("MODIFIED");                         // 저장하지 않음
    }
    answerDao.replace(surveyId, userId, answers);
    return Result.ok();
}
```

### 3) 비교와 갱신을 한 문장으로 (경쟁 조건까지 막을 때)
```sql
UPDATE documents SET body = ?, version = version + 1
 WHERE id = ? AND version = ?;      -- 갱신 행 수 0이면 다른 사람이 먼저 수정
```

## 주의할 점
- 버전 인자가 없으면(null) 비교를 건너뛰게 두면 구버전 클라이언트와 호환된다. 대신 모든 클라이언트(웹·모바일)를 함께 고쳐야 검사가 의미 있다.
- 서비스 메서드 시그니처를 바꾸면 개발 서버의 핫스왑으로는 반영되지 않는다. 완전히 재기동한 뒤 확인한다.
